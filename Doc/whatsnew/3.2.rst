PEP 384: Định nghĩa ABI ổn định
===============================

Trước đây, các extension module được xây dựng cho một phiên bản Python thường không thể sử dụng với các phiên bản Python khác. Đặc biệt trên Windows, mỗi bản phát hành tính năng của Python đều yêu cầu xây dựng lại tất cả extension module mà người dùng muốn sử dụng. Yêu cầu này xuất phát từ việc extension module có thể tự do truy cập vào các thành phần bên trong trình thông dịch Python.

Với Python 3.2, một cách tiếp cận thay thế đã khả dụng: các extension module tự giới hạn trong một API hạn chế (bằng cách định nghĩa Py_LIMITED_API) không thể sử dụng nhiều thành phần bên trong, nhưng bị giới hạn trong một tập hợp các hàm API được cam kết sẽ ổn định qua nhiều bản phát hành. Do đó, các extension module được xây dựng cho 3.2 theo chế độ này cũng sẽ hoạt động với 3.3, 3.4, v.v. Các extension module sử dụng những chi tiết của cấu trúc bộ nhớ vẫn có thể được xây dựng, nhưng sẽ cần biên dịch lại cho mỗi bản phát hành tính năng.

.. seealso::

   :pep:`384` - Xác định ABI ổn định
      PEP do Martin von Löwis biên soạn.


PEP 389: Mô-đun phân tích dòng lệnh Argparse
============================================

Một mô-đun mới để phân tích dòng lệnh, :mod:`argparse`, đã được giới thiệu nhằm khắc phục những hạn chế của :mod:`optparse`, vốn không hỗ trợ các đối số vị trí (không chỉ các tùy chọn), các lệnh con, các tùy chọn bắt buộc và những mẫu phổ biến khác để chỉ định và xác thực tùy chọn.

Mô-đun này đã đạt được thành công rộng rãi trong cộng đồng dưới dạng mô-đun bên thứ ba. Có nhiều tính năng đầy đủ hơn mô-đun tiền nhiệm,
mô-đun :mod:`argparse` hiện là mô-đun được ưu tiên để xử lý dòng lệnh. Mô-đun cũ vẫn được duy trì vì có một lượng lớn mã legacy phụ thuộc vào nó.

Dưới đây là một parser có chú thích minh họa các tính năng như giới hạn kết quả trong một tập hợp lựa chọn, chỉ định *metavar* trên màn hình trợ giúp, xác thực rằng có một hoặc nhiều đối số vị trí, và tạo một tùy chọn bắt buộc::

    import argparse
    parser = argparse.ArgumentParser(
                description = 'Manage servers',         # main description for help
                epilog = 'Tested on Solaris and Linux') # displayed after help
    parser.add_argument('action',                       # argument name
                choices = ['deploy', 'start', 'stop'],  # three allowed values
                help = 'action on each target')         # help msg
    parser.add_argument('targets',
                metavar = 'HOSTNAME',                   # var name used in help msg
                nargs = '+',                            # require one or more targets
                help = 'url for target machines')       # help msg explanation
    parser.add_argument('-u', '--user',                 # -u or --user option
                required = True,                        # make it a required argument
                help = 'login as user')

Ví dụ gọi parser trên một chuỗi lệnh::

    >>> cmd = 'deploy sneezy.example.com sleepy.example.com -u skycaptain'
    >>> result = parser.parse_args(cmd.split())
    >>> result.action
    'deploy'
    >>> result.targets
    ['sneezy.example.com', 'sleepy.example.com']
    >>> result.user
    'skycaptain'

Ví dụ về phần trợ giúp được parser tự động tạo::

    >>> parser.parse_args('-h'.split())

    usage: manage_cloud.py [-h] -u USER
                           {deploy,start,stop} HOSTNAME [HOSTNAME ...]

    Manage servers

    positional arguments:
      {deploy,start,stop}   action on each target
      HOSTNAME              url for target machines

    optional arguments:
      -h, --help            show this help message and exit
      -u USER, --user USER  login as user

    Tested on Solaris and Linux

Một tính năng :mod:`argparse` đặc biệt hữu ích là khả năng định nghĩa các subparser, mỗi subparser có các mẫu đối số và phần hiển thị trợ giúp riêng::

    import argparse
    parser = argparse.ArgumentParser(prog='HELM')
    subparsers = parser.add_subparsers()

    parser_l = subparsers.add_parser('launch', help='Launch Control')   # first subgroup
    parser_l.add_argument('-m', '--missiles', action='store_true')
    parser_l.add_argument('-t', '--torpedos', action='store_true')

    parser_m = subparsers.add_parser('move', help='Move Vessel',        # second subgroup
                                     aliases=('steer', 'turn'))         # equivalent names
    parser_m.add_argument('-c', '--course', type=int, required=True)
    parser_m.add_argument('-s', '--speed', type=int, default=0)

.. code-block:: shell-session

    $ ./helm.py --help                         # top level help (launch and move)
    $ ./helm.py launch --help                  # help for launch options
    $ ./helm.py launch --missiles              # set missiles=True and torpedos=False
    $ ./helm.py steer --course 180 --speed 5   # set movement parameters

PEP 391: Cấu hình Logging Dựa trên Từ điển
==========================================

Module :mod:`logging` cung cấp hai kiểu cấu hình: một kiểu sử dụng các lời gọi hàm cho từng tùy chọn, hoặc một kiểu khác được điều khiển bởi một tệp bên ngoài được lưu ở định dạng :mod:`configparser`. Các tùy chọn đó không cung cấp đủ tính linh hoạt để tạo cấu hình từ các tệp JSON hoặc YAML, cũng như không hỗ trợ cấu hình tăng dần, vốn cần thiết khi chỉ định các tùy chọn logger từ dòng lệnh.

Để hỗ trợ một kiểu linh hoạt hơn, module hiện cung cấp
:func:`logging.config.dictConfig` để chỉ định cấu hình logging bằng các dictionary Python thuần. Các tùy chọn cấu hình bao gồm formatter, handler, filter và logger. Dưới đây là một ví dụ hoạt động về một dictionary cấu hình::

   {"version": 1,
    "formatters": {"brief": {"format": "%(levelname)-8s: %(name)-15s: %(message)s"},
                   "full": {"format": "%(asctime)s %(name)-15s %(levelname)-8s %(message)s"}
                   },
    "handlers": {"console": {
                      "class": "logging.StreamHandler",
                      "formatter": "brief",
                      "level": "INFO",
                      "stream": "ext://sys.stdout"},
                 "console_priority": {
                      "class": "logging.StreamHandler",
                      "formatter": "full",
                      "level": "ERROR",
                      "stream": "ext://sys.stderr"}
                 },
    "root": {"level": "DEBUG", "handlers": ["console", "console_priority"]}}


Nếu dictionary đó được lưu trong một tệp có tên :file:`conf.json`, bạn có thể tải và gọi nó bằng đoạn mã như sau::

   >>> import json, logging.config
   >>> with open('conf.json') as f:
   ...     conf = json.load(f)
   ...
   >>> logging.config.dictConfig(conf)
   >>> logging.info("Transaction completed normally")
   INFO    : root           : Transaction completed normally
   >>> logging.critical("Abnormal termination")
   2011-02-17 11:14:36,694 root            CRITICAL Abnormal termination

.. seealso::

   :pep:`391` - Cấu hình logging dựa trên dictionary
      PEP do Vinay Sajip viết.


PEP 3148: Module ``concurrent.futures``
=======================================

Mã để tạo và quản lý tính đồng thời đang được tập hợp trong một namespace cấp cao nhất mới, *concurrent*. Thành phần đầu tiên là một package *futures*, cung cấp interface cấp cao thống nhất để quản lý thread và process.

Thiết kế của :mod:`concurrent.futures` được lấy cảm hứng từ package *java.util.concurrent*. Trong mô hình đó, một lời gọi đang chạy và kết quả của nó được biểu diễn bằng một đối tượng :class:`~concurrent.futures.Future`, trừu tượng hóa các tính năng chung cho thread, process và remote procedure call. Đối tượng này hỗ trợ kiểm tra trạng thái (đang chạy hoặc đã hoàn tất), timeout, hủy, thêm callback và truy cập kết quả hoặc exception.

Tính năng chính của module mới là một cặp executor class để khởi chạy và quản lý các lời gọi. Mục tiêu của các executor là giúp việc sử dụng những công cụ hiện có để thực hiện các lời gọi song song trở nên dễ dàng hơn. Chúng giúp tiết kiệm công sức cần thiết để thiết lập một pool tài nguyên, khởi chạy các lời gọi, tạo một hàng đợi kết quả, thêm cơ chế xử lý timeout và giới hạn tổng số thread, process hoặc remote procedure call.

Lý tưởng nhất là mỗi ứng dụng nên dùng chung một executor cho nhiều component để có thể quản lý tập trung các giới hạn process và thread. Điều này giải quyết thách thức trong thiết kế phát sinh khi mỗi component có chiến lược quản lý tài nguyên riêng và cạnh tranh với các component khác.

Cả hai class đều có chung một interface với ba phương thức:
:meth:`~concurrent.futures.Executor.submit` để lập lịch cho một callable và trả về một đối tượng :class:`~concurrent.futures.Future`;
:meth:`~concurrent.futures.Executor.map` để lập lịch nhiều lời gọi bất đồng bộ cùng lúc, và :meth:`~concurrent.futures.Executor.shutdown` để giải phóng tài nguyên. Class này là một :term:`context manager` và có thể được sử dụng trong một
:keyword:`with` statement để đảm bảo rằng các tài nguyên được tự động giải phóng khi các future đang chờ hoàn tất việc thực thi.

Một ví dụ đơn giản về :class:`~concurrent.futures.ThreadPoolExecutor` là khởi chạy bốn thread song song để sao chép các tệp.::

  import concurrent.futures, shutil
  with concurrent.futures.ThreadPoolExecutor(max_workers=4) as e:
      e.submit(shutil.copy, 'src1.txt', 'dest1.txt')
      e.submit(shutil.copy, 'src2.txt', 'dest2.txt')
      e.submit(shutil.copy, 'src3.txt', 'dest3.txt')
      e.submit(shutil.copy, 'src3.txt', 'dest4.txt')

      PEP do Brian Quinlan viết.

PEP 3147: Thư mục kho PYC
=========================

Cơ chế lưu vào bộ nhớ đệm bytecode của Python trong các tệp *.pyc* không hoạt động tốt trong những môi trường có nhiều trình thông dịch Python. Nếu một trình thông dịch gặp phải tệp bộ nhớ đệm do một trình thông dịch khác tạo ra, nó sẽ biên dịch lại mã nguồn và ghi đè lên tệp bộ nhớ đệm, khiến mất đi lợi ích của việc lưu vào bộ nhớ đệm.

Vấn đề "pyc fights" trở nên rõ rệt hơn khi các bản phân phối Linux ngày càng phổ biến việc cung cấp nhiều phiên bản Python. Những xung đột này cũng xảy ra với các biến thể CPython như Unladen Swallow.

Để giải quyết vấn đề này, cơ chế import của Python đã được mở rộng để sử dụng các tên tệp riêng cho từng trình thông dịch. Thay vì Python 3.2, Python 3.3 và Unladen Swallow cùng tranh giành một tệp có tên "mymodule.pyc", giờ đây chúng sẽ tìm kiếm lần lượt "mymodule.cpython-32.pyc", "mymodule.cpython-33.pyc" và "mymodule.unladen10.pyc". Ngoài ra, để ngăn tất cả các tệp mới này làm lộn xộn các thư mục mã nguồn, các tệp *pyc* giờ đây được tập hợp trong một thư mục "__pycache__" nằm bên dưới thư mục package.

Ngoài tên tệp và thư mục đích, cơ chế mới còn có một số khía cạnh mà lập trình viên có thể thấy được:

* Các module được import giờ đây có một thuộc tính :attr:`~module.__cached__` lưu tên của tệp thực tế đã được import:

   >>> import collections
   >>> collections.__cached__ # doctest: +SKIP
   'c:/py32/lib/__pycache__/collections.cpython-32.pyc'

* Thẻ riêng cho từng trình thông dịch có thể được truy cập từ module :mod:`!imp`:

   >>> import imp # doctest: +SKIP
   >>> imp.get_tag() # doctest: +SKIP
   'cpython-32'

* Các script cố gắng suy ra tên tệp mã nguồn từ tệp đã được import giờ đây cần thông minh hơn. Chỉ đơn giản xóa "c" khỏi tên tệp ".pyc" là không còn đủ nữa. Thay vào đó, hãy sử dụng các hàm mới trong module :mod:`!imp`:

  >>> imp.source_from_cache('c:/py32/lib/__pycache__/collections.cpython-32.pyc') # doctest: +SKIP
  'c:/py32/lib/collections.py'
  >>> imp.cache_from_source('c:/py32/lib/collections.py') # doctest: +SKIP
  'c:/py32/lib/__pycache__/collections.cpython-32.pyc'

* Các mô-đun :mod:`py_compile` và :mod:`compileall` đã được cập nhật để phản ánh quy ước đặt tên và thư mục đích mới. Lệnh gọi dòng lệnh của *compileall* có các tùy chọn mới: ``-i`` để chỉ định danh sách các tệp và thư mục cần biên dịch, và ``-b`` khiến các tệp bytecode được ghi vào vị trí cũ thay vì *__pycache__*.

* Mô-đun :mod:`importlib.abc` đã được cập nhật với các :term:`lớp cơ sở trừu tượng <abstract base class>` mới để tải các tệp bytecode. Các ABC lỗi thời, :class:`!PyLoader` và
  :class:`!PyPycLoader`, đã bị ngừng sử dụng (tài liệu có kèm hướng dẫn về cách duy trì khả năng tương thích với Python 3.1).

.. seealso::

   :pep:`3147` - Thư mục lưu trữ PYC
      PEP do Barry Warsaw viết.


PEP 3149: Tệp .so được gắn thẻ phiên bản ABI
============================================

Thư mục lưu trữ PYC cho phép đặt nhiều tệp bộ nhớ đệm bytecode cùng một vị trí. PEP này triển khai một cơ chế tương tự cho các tệp shared object bằng cách cung cấp cho chúng một thư mục dùng chung và các tên riêng biệt cho từng phiên bản.

Thư mục chung là "pyshared" và tên tệp được phân biệt bằng cách xác định implementation Python (chẳng hạn như CPython, PyPy, Jython, v.v.), số phiên bản chính và phụ, cùng các cờ build tùy chọn (chẳng hạn như "d" cho debug, "m" cho pymalloc, "u" cho wide-unicode). Với một package tùy ý "foo", bạn có thể thấy các tệp sau khi distribution package được cài đặt::

   /usr/share/pyshared/foo.cpython-32m.so
   /usr/share/pyshared/foo.cpython-33md.so

Trong chính Python, bạn có thể truy cập các tag thông qua các hàm trong module :mod:`sysconfig`::

   >>> import sysconfig
   >>> sysconfig.get_config_var('SOABI')       # find the version tag
   'cpython-32mu'
   >>> sysconfig.get_config_var('EXT_SUFFIX')  # find the full filename extension
   '.cpython-32mu.so'

.. seealso::

   :pep:`3149` - Tệp .so được gắn thẻ phiên bản ABI
      PEP do Barry Warsaw viết.


PEP 3333: Giao diện Cổng Máy chủ Web Python v1.0.1
==================================================

PEP thông tin này làm rõ cách xử lý các vấn đề về bytes/text trong giao thức WSGI. Thách thức nằm ở chỗ việc xử lý chuỗi trong Python 3 thuận tiện nhất khi sử dụng kiểu :class:`str`, mặc dù bản thân giao thức HTTP hướng đến bytes.

PEP phân biệt các *chuỗi native* được sử dụng cho header và metadata của request/response với các *chuỗi byte* được sử dụng cho phần thân của request và response.

Các *chuỗi native* luôn có kiểu :class:`str` nhưng bị giới hạn ở các code point từ *U+0000* đến *U+00FF*, có thể chuyển đổi thành byte bằng encoding *Latin-1*. Các chuỗi này được dùng làm khóa và giá trị trong từ điển môi trường, cũng như cho các header và trạng thái phản hồi trong
hàm :func:`!start_response`. Chúng phải tuân theo :rfc:`2616` về encoding. Nghĩa là chúng либо phải là các ký tự *ISO-8859-1* hoặc sử dụng
:rfc:`2047` encoding MIME.

Đối với các developer chuyển ứng dụng WSGI từ Python 2, sau đây là những điểm chính:

* Nếu ứng dụng đã sử dụng chuỗi cho các header trong Python 2 thì không cần thay đổi gì.

* Ngược lại, nếu ứng dụng đã encode các header đầu ra hoặc decode các header đầu vào thì cần encode lại các header đó sang Latin-1. Ví dụ, một header đầu ra được encode bằng utf-8 và sử dụng ``h.encode('utf-8')`` giờ đây cần được chuyển đổi từ byte sang chuỗi native bằng ``h.encode('utf-8').decode('latin-1')``.

* Các giá trị do ứng dụng yield hoặc gửi bằng phương thức :meth:`!write` phải là chuỗi byte. Hàm :func:`!start_response` và environ phải sử dụng chuỗi native. Không thể trộn lẫn hai loại này.

Đối với những người triển khai server viết các luồng chuyển tiếp CGI-to-WSGI hoặc các giao thức kiểu CGI khác, người dùng phải có thể truy cập môi trường bằng các chuỗi native, dù nền tảng bên dưới có thể sử dụng một quy ước khác. Để khắc phục khoảng cách này, mô-đun :mod:`wsgiref` đã có một hàm mới,
:func:`wsgiref.handlers.read_environ` để chuyển mã các biến CGI từ
:data:`os.environ` thành các chuỗi native và trả về một dictionary mới.

      PEP do Phillip Eby viết.


Các thay đổi khác trong ngôn ngữ
================================

Một số thay đổi nhỏ hơn đối với ngôn ngữ Python cốt lõi gồm có:

* Việc định dạng chuỗi cho :func:`format` và :meth:`str.format` đã có thêm khả năng mới đối với ký tự định dạng **#**. Trước đây, với các số nguyên ở dạng nhị phân, bát phân hoặc thập lục phân, tùy theo từng trường hợp, nó khiến kết quả được thêm tiền tố '0b', '0o' hoặc '0x'. Giờ đây, nó cũng có thể xử lý số thực, số phức và Decimal, khiến kết quả luôn có dấu thập phân ngay cả khi không có chữ số nào theo sau.

  >>> format(20, '#o')
  '0o24'
  >>> format(12.34, '#5.0f')
  '  12.'

  (Do Mark Dickinson đề xuất và Eric Smith triển khai trong :issue:`7094`.)

* Ngoài ra còn có một phương thức :meth:`str.format_map` mới, mở rộng khả năng của phương thức :meth:`str.format` hiện có bằng cách chấp nhận các
  đối tượng :term:`mapping` tùy ý. Phương thức mới này cho phép sử dụng việc định dạng chuỗi với bất kỳ đối tượng nào trong số rất nhiều đối tượng giống từ điển của Python, chẳng hạn như
  :class:`~collections.defaultdict`, :class:`~shelve.Shelf`,
  :class:`~configparser.ConfigParser`, hoặc :mod:`dbm`. Nó cũng hữu ích với các lớp con :class:`dict` tùy chỉnh, có chức năng chuẩn hóa khóa trước khi tra cứu hoặc cung cấp phương thức :meth:`~object.__missing__` cho các khóa không xác định::

    >>> import shelve
    >>> d = shelve.open('tmp.shl')
    >>> 'The {project_name} status is {status} as of {date}'.format_map(d)
    'The testing project status is green as of February 15, 2011'

    >>> class LowerCasedDict(dict):
    ...     def __getitem__(self, key):
    ...         return dict.__getitem__(self, key.lower())
    ...
    >>> lcd = LowerCasedDict(part='widgets', quantity=10)
    >>> 'There are {QUANTITY} {Part} in stock'.format_map(lcd)
    'There are 10 widgets in stock'

    >>> class PlaceholderDict(dict):
    ...     def __missing__(self, key):
    ...         return '<{}>'.format(key)
    ...
    >>> 'Hello {name}, welcome to {location}'.format_map(PlaceholderDict())
    'Hello <name>, welcome to <location>'

 (Do Raymond Hettinger đề xuất và Eric Smith triển khai trong
 :issue:`6081`.)

* Giờ đây, trình thông dịch có thể được khởi động với tùy chọn quiet, ``-q``, để ngăn thông tin bản quyền và phiên bản được hiển thị trong chế độ tương tác. Có thể kiểm tra tùy chọn này bằng thuộc tính :data:`sys.flags`:

  .. code-block:: shell-session

    $ python -q
    >>> sys.flags
    sys.flags(debug=0, division_warning=0, inspect=0, interactive=0,
    optimize=0, dont_write_bytecode=0, no_user_site=0, no_site=0,
    ignore_environment=0, verbose=0, bytes_warning=0, quiet=1)

  (Đóng góp của Marcin Wojdyr trong :issue:`1772833`).

* Hàm :func:`hasattr` hoạt động bằng cách gọi :func:`getattr` và phát hiện xem có exception nào được raised hay không. Kỹ thuật này cho phép nó phát hiện các method được tạo động bởi :meth:`~object.__getattr__` hoặc :meth:`~object.__getattribute__`, vốn nếu không sẽ không có trong class dictionary. Trước đây, *hasattr* sẽ bắt mọi exception, có thể che giấu các lỗi thực sự. Giờ đây, *hasattr* đã được siết chặt để chỉ bắt :exc:`AttributeError` và cho các exception khác truyền lên::

    >>> class A:
    ...     @property
    ...     def f(self):
    ...         return 1 // 0
    ...
    >>> a = A()
    >>> hasattr(a, 'f')
    Traceback (most recent call last):
      ...
    ZeroDivisionError: integer division or modulo by zero

  (Được Yury Selivanov phát hiện và Benjamin Peterson sửa; :issue:`9666`.)

* :func:`str` của một số float hoặc complex giờ đây giống với
  :func:`repr` của nó. Trước đây, dạng :func:`str` ngắn hơn, nhưng điều đó chỉ gây nhầm lẫn và giờ không còn cần thiết nữa, vì dạng ngắn nhất có thể
  :func:`repr` giờ đây được hiển thị theo mặc định:

   >>> import math
   >>> repr(math.pi)
   '3.141592653589793'
   >>> str(math.pi)
   '3.141592653589793'

  (Được Mark Dickinson đề xuất và triển khai; :issue:`9337`.)

* Các đối tượng :class:`memoryview` hiện có phương thức :meth:`~memoryview.release` và giờ đây cũng hỗ trợ giao thức quản lý ngữ cảnh. Điều này cho phép giải phóng kịp thời mọi tài nguyên đã được thu nhận khi yêu cầu một buffer từ đối tượng ban đầu.

  >>> with memoryview(b'abcdefgh') as v:
  ...     print(v.tolist())
  [97, 98, 99, 100, 101, 102, 103, 104]

  (Do Antoine Pitrou bổ sung; :issue:`9757`.)

* Trước đây, không được phép xóa một tên khỏi namespace cục bộ nếu tên đó xuất hiện dưới dạng biến tự do trong một block lồng nhau::

       def outer(x):
           def inner():
               return x
           inner()
           del x

  Giờ đây thao tác này được phép. Hãy nhớ rằng đích của mệnh đề :keyword:`except` sẽ bị xóa, vì vậy đoạn mã này vốn hoạt động với Python 2.6 nhưng đã phát sinh lỗi
  :exc:`SyntaxError` với Python 3.1 và giờ đây lại hoạt động::

       def f():
           def print_error():
               print(e)
           try:
               something
           except Exception as e:
               print_error()
               # implicit "del e" here

  (Xem :issue:`4617`.)

* :ref:`Các kiểu chuỗi Struct <struct-sequence-objects>` giờ đây là các lớp con của tuple. Điều này có nghĩa là các cấu trúc C như những cấu trúc được trả về bởi :func:`os.stat`,
  :func:`time.gmtime` và :data:`sys.version_info` giờ hoạt động giống như một
  :term:`named tuple` và giờ hoạt động với các hàm và phương thức yêu cầu một tuple làm đối số. Đây là một bước tiến lớn trong việc làm cho các cấu trúc C linh hoạt như các cấu trúc Python thuần túy tương ứng:

  >>> import sys
  >>> isinstance(sys.version_info, tuple)
  True
  >>> 'Version %d.%d.%d %s(%d)' % sys.version_info # doctest: +SKIP
  'Version 3.2.0 final(0)'

  (Do Arfrever Frehtes Taifersar Arahesis đề xuất và Benjamin Peterson triển khai trong :issue:`8413`.)

* Giờ đây, các cảnh báo dễ kiểm soát hơn khi sử dụng biến môi trường :envvar:`PYTHONWARNINGS` thay cho việc sử dụng ``-W`` trên dòng lệnh:

  .. code-block:: shell-session

    $ export PYTHONWARNINGS='ignore::RuntimeWarning::,once::UnicodeWarning::'

  (Do Barry Warsaw đề xuất và Philip Jenvey triển khai trong :issue:`7301`.)

* Một danh mục cảnh báo mới, :exc:`ResourceWarning`, đã được thêm vào. Cảnh báo này được phát ra khi phát hiện các vấn đề tiềm ẩn liên quan đến việc sử dụng hoặc dọn dẹp tài nguyên. Theo mặc định, cảnh báo này bị tắt trong các bản build phát hành thông thường, nhưng có thể được bật bằng các phương tiện do mô-đun :mod:`warnings` cung cấp hoặc trên dòng lệnh.

  Một :exc:`ResourceWarning` được phát ra khi trình thông dịch tắt nếu
  :data:`gc.garbage` list không rỗng và nếu :const:`gc.DEBUG_UNCOLLECTABLE` được thiết lập, tất cả các đối tượng không thể thu gom sẽ được in ra.  Điều này nhằm giúp lập trình viên nhận biết rằng mã của họ có vấn đề về việc hoàn tất đối tượng.

  Một :exc:`ResourceWarning` cũng được phát ra khi một :term:`file object` bị hủy mà chưa được đóng một cách rõ ràng.  Mặc dù deallocator của đối tượng đó đảm bảo đóng tài nguyên hệ điều hành bên dưới (thường là một file descriptor), việc trì hoãn giải phóng đối tượng có thể gây ra nhiều vấn đề khác nhau, đặc biệt là trên Windows.  Sau đây là một ví dụ về cách bật cảnh báo từ dòng lệnh:

  .. code-block:: shell-session

      $ python -q -Wdefault
      >>> f = open("foo", "wb")
      >>> del f
      __main__:1: ResourceWarning: unclosed file <_io.BufferedWriter name='foo'>

  (Do Antoine Pitrou và Georg Brandl bổ sung trong :issue:`10093` và :issue:`477863`.)

* Các đối tượng :class:`range` hiện hỗ trợ các phương thức *index* và *count*. Đây là một phần trong nỗ lực giúp nhiều đối tượng triển khai đầy đủ hơn
  :class:`collections.Sequence <collections.abc.Sequence>` :term:`abstract base class`.  Nhờ đó, ngôn ngữ sẽ có một API thống nhất hơn.  Ngoài ra, các đối tượng :class:`range` hiện hỗ trợ slicing và chỉ mục âm, ngay cả với các giá trị lớn hơn
  :data:`sys.maxsize`.  Điều này giúp *range* tương tác tốt hơn với các list::

      >>> range(0, 100, 2).count(10)
      1
      >>> range(0, 100, 2).index(10)
      5
      >>> range(0, 100, 2)[5]
      10
      >>> range(0, 100, 2)[0:5]
      range(0, 10, 2)

  (Do Daniel Stutzbach đóng góp trong :issue:`9213`, Alexander Belopolsky trong :issue:`2690` và Nick Coghlan trong :issue:`10889`.)

* Hàm dựng sẵn :func:`callable` từ Py2.x đã được khôi phục. Hàm này cung cấp một lựa chọn ngắn gọn, dễ đọc thay cho việc sử dụng :term:`abstract base class` trong một biểu thức như ``isinstance(x, collections.Callable)``:

  >>> callable(max)
  True
  >>> callable(20)
  False

  (Xem :issue:`10518`.)

* Cơ chế import của Python giờ đây có thể tải các module được cài đặt trong những thư mục có ký tự không phải ASCII trong tên đường dẫn. Điều này đã giải quyết một vấn đề gây khó chịu với các thư mục home của người dùng có ký tự không phải ASCII trong tên người dùng.

 (Đòi hỏi Victor Stinner phải thực hiện nhiều công việc trong :issue:`9425`.)


Các module mới, được cải tiến và không còn được khuyến nghị
===========================================================

Thư viện chuẩn của Python đã trải qua những nỗ lực bảo trì đáng kể và các cải tiến về chất lượng.

Tin tức lớn nhất đối với Python 3.2 là package :mod:`email`, module :mod:`mailbox` và các module :mod:`!nntplib` giờ đây hoạt động chính xác với mô hình bytes/text trong Python 3. Lần đầu tiên, các thông điệp có encoding hỗn hợp được xử lý chính xác.

Trong toàn bộ standard library, encodings và các vấn đề liên quan đến text so với bytes đã được chú trọng cẩn thận hơn. Cụ thể, việc tương tác với hệ điều hành hiện có khả năng trao đổi dữ liệu non-ASCII tốt hơn bằng encoding Windows MBCS, các encoding nhận biết locale hoặc UTF-8.

Một cải tiến đáng kể khác là việc bổ sung hỗ trợ tốt hơn rất nhiều cho các kết nối *SSL* và chứng chỉ bảo mật.

Ngoài ra, hiện có thêm nhiều class triển khai :term:`context manager` để hỗ trợ dọn dẹp tài nguyên thuận tiện và đáng tin cậy bằng câu lệnh :keyword:`with`.

email
-----

Tính dễ sử dụng của package :mod:`email` trong Python 3 phần lớn đã được khắc phục nhờ những nỗ lực đáng kể của R. David Murray. Vấn đề là email thường được đọc và lưu trữ dưới dạng :class:`bytes` thay vì text :class:`str`, đồng thời có thể chứa nhiều encoding trong cùng một email. Vì vậy, package email phải được mở rộng để phân tích cú pháp và tạo các thông điệp email ở định dạng bytes.

* Các hàm mới :func:`~email.message_from_bytes` và
  :func:`~email.message_from_binary_file`, cùng các class mới
  :class:`~email.parser.BytesFeedParser` và :class:`~email.parser.BytesParser` cho phép phân tích dữ liệu thông báo nhị phân thành các đối tượng model.

* Khi model nhận đầu vào là bytes, :meth:`~email.message.Message.get_payload` theo mặc định sẽ giải mã phần nội dung thông báo có một
  :mailheader:`Content-Transfer-Encoding` là *8bit* bằng charset được chỉ định trong các header MIME và trả về chuỗi thu được.

* Khi model nhận đầu vào là bytes, :class:`~email.generator.Generator` sẽ chuyển đổi các phần nội dung thông báo có :mailheader:`Content-Transfer-Encoding` là *8bit* để thay vào đó có *7bit* :mailheader:`Content-Transfer-Encoding`.

  Các header có byte non-ASCII chưa được mã hóa được xem là :rfc:`2047`\ -encoded bằng bộ ký tự *unknown-8bit*.

* Một class mới :class:`~email.generator.BytesGenerator` tạo bytes làm đầu ra, giữ nguyên mọi dữ liệu non-ASCII không thay đổi có trong đầu vào được dùng để xây dựng model, bao gồm các phần nội dung thông báo có một
  :mailheader:`Content-Transfer-Encoding` là *8bit*.

* Lớp :mod:`smtplib` :class:`~smtplib.SMTP` hiện chấp nhận một chuỗi byte cho đối số *msg* của phương thức :meth:`~smtplib.SMTP.sendmail`, và một phương thức mới, :meth:`~smtplib.SMTP.send_message` chấp nhận một
  đối tượng :class:`~email.message.Message` và có thể tùy chọn lấy trực tiếp các địa chỉ *from_addr* và *to_addrs* từ đối tượng.

(Được đề xuất và triển khai bởi R. David Murray, :issue:`4661` và :issue:`10321`.)

elementtree
-----------

Gói :mod:`xml.etree.ElementTree` và phiên bản :mod:`!xml.etree.cElementTree` tương ứng đã được cập nhật lên phiên bản 1.3.

Một số hàm và phương thức mới, hữu ích đã được bổ sung:

* :meth:`xml.etree.ElementTree.Element.extend` để nối thêm một chuỗi gồm không hoặc nhiều phần tử

functools
---------

* Mô-đun :mod:`functools` bao gồm một decorator mới để lưu vào bộ nhớ đệm các lệnh gọi hàm. :deco:`functools.lru_cache` có thể tránh việc truy vấn lặp lại một tài nguyên bên ngoài bất cứ khi nào kết quả được dự kiến là giống nhau.

  Ví dụ: thêm một decorator caching vào hàm truy vấn cơ sở dữ liệu có thể giảm số lần truy cập cơ sở dữ liệu đối với các tìm kiếm phổ biến:

  >>> import functools
  >>> @functools.lru_cache(maxsize=300)
  ... def get_phone_number(name):
  ...     c = conn.cursor()
  ...     c.execute('SELECT phonenumber FROM phonelist WHERE name=?', (name,))
  ...     return c.fetchone()[0]

  >>> for name in user_requests:        # doctest: +SKIP
  ...     get_phone_number(name)        # cached lookup

  Để hỗ trợ việc chọn kích thước cache hiệu quả, hàm được bọc sẽ được instrument để theo dõi các thống kê của cache:

  >>> get_phone_number.cache_info()     # doctest: +SKIP
  CacheInfo(hits=4805, misses=980, maxsize=300, currsize=300)

  Nếu bảng phonelist được cập nhật, có thể xóa nội dung đã lỗi thời của cache bằng cách:

  >>> get_phone_number.cache_clear()

  (Đóng góp của Raymond Hettinger và kết hợp các ý tưởng thiết kế từ Jim Baker, Miki Tebeka và Nick Coghlan; xem `công thức 498245 <https://code.activestate.com/recipes/498245-lru-and-lfu-cache-decorators/>`_\, `công thức 577479 <https://code.activestate.com/recipes/577479-simple-caching-decorator/>`_\, :issue:`10586`, và
  :issue:`10593`.)

* Decorator :deco:`functools.wraps` hiện thêm một thuộc tính :attr:`__wrapped__` trỏ đến hàm callable ban đầu. Điều này cho phép introspect các hàm được bọc. Nó cũng sao chép :attr:`~function.__annotations__` nếu được định nghĩa. Giờ đây, nó cũng bỏ qua một cách an toàn các thuộc tính bị thiếu như
  :attr:`~function.__doc__` có thể chưa được định nghĩa cho callable được bọc.

  Trong ví dụ trên, có thể xóa cache bằng cách khôi phục hàm ban đầu:

  >>> get_phone_number = get_phone_number.__wrapped__    # uncached function

  (Do Nick Coghlan và Terrence Cole; :issue:`9567`, :issue:`3445`, và
  :issue:`8814`.)

* Để giúp viết các class có những phương thức so sánh nâng cao, một decorator mới
  :deco:`functools.total_ordering` sẽ sử dụng các phương thức bằng và không bằng hiện có để hoàn thiện những phương thức còn lại.

  Ví dụ, việc cung cấp *__eq__* và *__lt__* sẽ cho phép
  :deco:`~functools.total_ordering` hoàn thiện *__le__*, *__gt__* và *__ge__*::

    @total_ordering
    class Student:
        def __eq__(self, other):
            return ((self.lastname.lower(), self.firstname.lower()) ==
                    (other.lastname.lower(), other.firstname.lower()))

        def __lt__(self, other):
            return ((self.lastname.lower(), self.firstname.lower()) <
                    (other.lastname.lower(), other.firstname.lower()))

  Với decorator *total_ordering*, các phương thức so sánh còn lại sẽ được tự động hoàn thiện.

  (Do Raymond Hettinger đóng góp.)

* Để hỗ trợ chuyển các chương trình từ Python 2, hàm :func:`functools.cmp_to_key` chuyển một hàm so sánh kiểu cũ thành :term:`key function` hiện đại:

  >>> # locale-aware sort order
  >>> sorted(iterable, key=cmp_to_key(locale.strcoll)) # doctest: +SKIP

  Để xem các ví dụ về sắp xếp và hướng dẫn ngắn về sắp xếp, hãy xem hướng dẫn `Sorting HowTo <https://wiki.python.org/moin/HowTo/Sorting/>`_.

  (Do Raymond Hettinger đóng góp.)

collections
-----------

* Lớp :class:`collections.Counter` hiện có hai dạng phép trừ tại chỗ, toán tử *-=* hiện có để thực hiện `phép trừ bão hòa <https://en.wikipedia.org/wiki/Saturation_arithmetic>`_ và dạng mới
  phương thức :meth:`~collections.Counter.subtract` để thực hiện phép trừ thông thường. Dạng trước phù hợp với `multiset <https://en.wikipedia.org/wiki/Multiset>`_ chỉ có số lượng dương, còn dạng sau phù hợp hơn với các trường hợp cho phép số lượng âm:

  >>> from collections import Counter
  >>> tally = Counter(dogs=5, cats=3)
  >>> tally -= Counter(dogs=2, cats=8)    # saturating subtraction
  >>> tally
  Counter({'dogs': 3})

  >>> tally = Counter(dogs=5, cats=3)
  >>> tally.subtract(dogs=2, cats=8)      # regular subtraction
  >>> tally
  Counter({'dogs': 3, 'cats': -5})

  (Đóng góp của Raymond Hettinger.)

* Lớp :class:`collections.OrderedDict` có một phương thức mới
  :meth:`~collections.OrderedDict.move_to_end`, nhận một key hiện có và chuyển nó đến vị trí đầu tiên hoặc cuối cùng trong chuỗi có thứ tự.

  Mặc định là chuyển một mục đến vị trí cuối cùng. Điều này tương đương với việc làm mới một mục bằng ``od[k] = od.pop(k)``.

  Một thao tác move-to-end nhanh rất hữu ích để sắp xếp lại các mục. Ví dụ: có thể dùng một ordered dictionary để theo dõi thứ tự truy cập bằng cách loại dần các mục từ cũ nhất đến mục vừa được truy cập gần đây nhất.

  >>> from collections import OrderedDict
  >>> d = OrderedDict.fromkeys(['a', 'b', 'X', 'd', 'e'])
  >>> list(d)
  ['a', 'b', 'X', 'd', 'e']
  >>> d.move_to_end('X')
  >>> list(d)
  ['a', 'b', 'd', 'e', 'X']

  (Đóng góp của Raymond Hettinger.)

* Lớp :class:`collections.deque` được bổ sung hai phương thức mới
  :meth:`~collections.deque.count` và :meth:`~collections.deque.reverse`, giúp chúng có thể thay thế cho các đối tượng :class:`list` dễ dàng hơn:

  >>> from collections import deque
  >>> d = deque('simsalabim')
  >>> d.count('s')
  2
  >>> d.reverse()
  >>> d
  deque(['m', 'i', 'b', 'a', 'l', 'a', 's', 'm', 'i', 's'])

  (Đóng góp của Raymond Hettinger.)

threading
---------

Module :mod:`threading` có một lớp đồng bộ hóa :class:`~threading.Barrier` mới, cho phép nhiều thread chờ cho đến khi tất cả đã đến cùng một điểm barrier. Barrier hữu ích để đảm bảo rằng một tác vụ có nhiều điều kiện tiên quyết sẽ không chạy cho đến khi tất cả các tác vụ tiền nhiệm hoàn tất.

Barrier có thể hoạt động với số lượng thread bất kỳ. Đây là sự khái quát hóa của `điểm hẹn (Rendezvous) <https://en.wikipedia.org/wiki/Synchronous_rendezvous>`_, vốn chỉ được định nghĩa cho hai thread.

Được triển khai dưới dạng barrier tuần hoàn hai pha, các đối tượng :class:`~threading.Barrier` này thích hợp để sử dụng trong các vòng lặp. Hai pha riêng biệt *lấp đầy* và *rút cạn* đảm bảo rằng tất cả thread đều được giải phóng (rút cạn) trước khi bất kỳ thread nào có thể lặp lại và tham gia lại barrier. Barrier được đặt lại hoàn toàn sau mỗi chu kỳ.

Ví dụ sử dụng barrier::

    from threading import Barrier, Thread

    def get_votes(site):
        ballots = conduct_election(site)
        all_polls_closed.wait()        # do not count until all polls are closed
        totals = summarize(ballots)
        publish(site, totals)

    all_polls_closed = Barrier(len(sites))
    for site in sites:
        Thread(target=get_votes, args=(site,)).start()

Trong ví dụ này, barrier thực thi quy tắc rằng không thể kiểm phiếu tại bất kỳ điểm bỏ phiếu nào cho đến khi tất cả điểm bỏ phiếu đóng cửa. Lưu ý rằng giải pháp sử dụng barrier tương tự như giải pháp sử dụng :meth:`threading.Thread.join`, nhưng các thread vẫn hoạt động và tiếp tục thực hiện công việc (tổng hợp phiếu) sau khi vượt qua điểm barrier.

Nếu bất kỳ tác vụ tiền nhiệm nào có thể bị treo hoặc trì hoãn, bạn có thể tạo barrier với tham số *timeout* tùy chọn. Khi đó, nếu khoảng thời gian chờ hết trước khi tất cả tác vụ tiền nhiệm đến điểm barrier, mọi thread đang chờ sẽ được giải phóng và một ngoại lệ :exc:`~threading.BrokenBarrierError` được phát sinh::

    def get_votes(site):
        ballots = conduct_election(site)
        try:
            all_polls_closed.wait(timeout=midnight - time.now())
        except BrokenBarrierError:
            lockbox = seal_ballots(ballots)
            queue.put(lockbox)
        else:
            totals = summarize(ballots)
            publish(site, totals)

Trong ví dụ này, barrier thực thi một quy tắc mạnh mẽ hơn. Nếu một số điểm bầu cử không hoàn tất trước nửa đêm, barrier sẽ hết thời gian chờ, còn các lá phiếu sẽ được niêm phong và đưa vào một queue để xử lý sau.

Xem `Các mẫu đồng bộ hóa bằng barrier <https://osl.cs.illinois.edu/media/papers/karmani-2009-barrier_synchronization_pattern.pdf>`_ để biết thêm ví dụ về cách sử dụng barrier trong tính toán song song. Ngoài ra, `The Little Book of Semaphores <https://greenteapress.com/semaphores/LittleBookOfSemaphores.pdf>`_, *phần 3.6* có phần giải thích đơn giản nhưng đầy đủ về barrier.

(Do Kristján Valur Jónsson đóng góp, với phần đánh giá API của Jeffrey Yasskin trong
:issue:`8777`.)

datetime và time
----------------

* Mô-đun :mod:`datetime` có một kiểu mới :class:`~datetime.timezone`, triển khai giao diện :class:`~datetime.tzinfo` bằng cách trả về một độ lệch UTC và tên múi giờ cố định. Điều này giúp việc tạo các đối tượng datetime nhận biết múi giờ trở nên dễ dàng hơn::

    >>> import datetime as dt

    >>> dt.datetime.now(dt.timezone.utc)
    datetime.datetime(2010, 12, 8, 21, 4, 2, 923754, tzinfo=datetime.timezone.utc)

    >>> dt.datetime.strptime("01/01/2000 12:00 +0000", "%m/%d/%Y %H:%M %z")
    datetime.datetime(2000, 1, 1, 12, 0, tzinfo=datetime.timezone.utc)

* Ngoài ra, các đối tượng :class:`~datetime.timedelta` giờ đây có thể được nhân với
  :class:`float` và chia cho các đối tượng :class:`float` và :class:`int`. Các đối tượng :class:`~datetime.timedelta` giờ đây cũng có thể chia cho nhau.

* Phương thức :meth:`datetime.date.strftime` không còn bị giới hạn ở các năm sau năm 1900. Phạm vi năm được hỗ trợ mới là từ 1000 đến 9999, bao gồm cả hai đầu mút.

* Bất cứ khi nào sử dụng năm có hai chữ số trong một bộ thời gian, cách diễn giải đều được :data:`!time.accept2dyear` chi phối. Giá trị mặc định là ``True``, nghĩa là đối với năm có hai chữ số, thế kỷ được suy đoán theo các quy tắc POSIX chi phối định dạng strptime ``%y``.

  Bắt đầu từ Py3.2, việc sử dụng heuristic đoán thế kỷ sẽ phát ra một
  :exc:`DeprecationWarning`.  Thay vào đó, khuyến nghị rằng
  :data:`!time.accept2dyear` được đặt thành ``False`` để có thể sử dụng các khoảng ngày lớn mà không cần phỏng đoán::

    >>> import time, warnings
    >>> warnings.resetwarnings()      # remove the default warning filters

    >>> time.accept2dyear = True      # guess whether 11 means 11 or 2011
    >>> time.asctime((11, 1, 1, 12, 34, 56, 4, 1, 0))
    Warning (from warnings module):
      ...
    DeprecationWarning: Century info guessed for a 2-digit year.
    'Fri Jan  1 12:34:56 2011'

    >>> time.accept2dyear = False     # use the full range of allowable dates
    >>> time.asctime((11, 1, 1, 12, 34, 56, 4, 1, 0))
    'Fri Jan  1 12:34:56 11'

  Một số hàm hiện có khoảng ngày được mở rộng đáng kể.  Khi
  :data:`!time.accept2dyear` là false, hàm :func:`time.asctime` sẽ chấp nhận mọi năm phù hợp với kiểu int C, trong khi :func:`time.mktime` và
  các hàm :func:`time.strftime` sẽ chấp nhận toàn bộ phạm vi được các hàm tương ứng của hệ điều hành hỗ trợ.

:issue:`5094`, :issue:`6641`, :issue:`2706`, :issue:`1777412`, :issue:`8013` và :issue:`10827`.)

math
----

Mô-đun :mod:`math` đã được cập nhật với sáu hàm mới lấy cảm hứng từ tiêu chuẩn C99.

Hàm :func:`~math.isfinite` cung cấp một cách đáng tin cậy và nhanh chóng để phát hiện các giá trị đặc biệt. Hàm trả về ``True`` đối với các số thông thường và ``False`` đối với *Nan* hoặc *Infinity*:

>>> from math import isfinite
>>> [isfinite(x) for x in (123, 4.56, float('Nan'), float('Inf'))]
[True, True, False, False]

Hàm :func:`~math.expm1` tính ``e**x-1`` cho các giá trị nhỏ của *x* mà không gây ra mất độ chính xác như thường xảy ra khi trừ các đại lượng gần bằng nhau:

>>> from math import expm1
>>> expm1(0.013671875)   # more accurate way to compute e**x-1 for a small x
0.013765762467652909

Hàm :func:`~math.erf` tính một tích phân xác suất, hay `hàm sai số Gaussian <https://en.wikipedia.org/wiki/Error_function>`_. Hàm sai số bù, :func:`~math.erfc`, được ``1 - erf(x)``:

.. doctest::
   :options: +SKIP

   >>> from math import erf, erfc, sqrt
   >>> erf(1.0/sqrt(2.0))   # portion of normal distribution within 1 standard deviation
   0.682689492137086
   >>> erfc(1.0/sqrt(2.0))  # portion of normal distribution outside 1 standard deviation
   0.31731050786291404
   >>> erf(1.0/sqrt(2.0)) + erfc(1.0/sqrt(2.0))
   1.0

Hàm :func:`~math.gamma` là phần mở rộng liên tục của hàm giai thừa. Xem https://en.wikipedia.org/wiki/Gamma_function để biết chi tiết. Vì hàm này có liên quan đến các giai thừa nên nó tăng nhanh ngay cả với các giá trị nhỏ của *x*, do đó cũng có hàm :func:`~math.lgamma` để tính logarit tự nhiên của hàm gamma:

>>> from math import gamma, lgamma
>>> gamma(7.0)           # six factorial
720.0
>>> lgamma(801.0)        # log(800 factorial)
4551.950730698041

reprlib
-------

Khi viết một phương thức :meth:`~object.__repr__` cho một container tùy chỉnh, bạn rất dễ quên xử lý trường hợp một thành viên tham chiếu ngược lại chính container đó. Các đối tượng dựng sẵn của Python như :class:`list` và :class:`set` xử lý tham chiếu đến chính đối tượng bằng cách hiển thị "..." trong phần đệ quy của chuỗi biểu diễn.

Để hỗ trợ viết các phương thức :meth:`~object.__repr__` như vậy, module :mod:`reprlib` có một decorator mới là :deco:`~reprlib.recursive_repr`, dùng để phát hiện các lời gọi đệ quy đến
:meth:`!__repr__` và thay thế chúng bằng một chuỗi giữ chỗ::

        >>> class MyList(list):
        ...     @recursive_repr()
        ...     def __repr__(self):
        ...         return '<' + '|'.join(map(repr, self)) + '>'
        ...
        >>> m = MyList('abc')
        >>> m.append(m)
        >>> m.append('x')
        >>> print(m)
        <'a'|'b'|'c'|...|'x'>

logging
-------

Ngoài cấu hình dựa trên dictionary được mô tả ở trên,
:mod:`logging` package còn có nhiều cải tiến khác.

Tài liệu logging đã được bổ sung :ref:`hướng dẫn cơ bản <logging-basic-tutorial>`\, một :ref:`hướng dẫn nâng cao <logging-advanced-tutorial>`\, và một :ref:`sổ tay công thức <logging-cookbook>` về các công thức logging. Đây là cách nhanh nhất để tìm hiểu về logging.

Hàm :func:`logging.basicConfig` thiết lập đã có thêm đối số *style* để hỗ trợ ba kiểu định dạng chuỗi khác nhau. Mặc định, đối số này là "%" cho kiểu định dạng %-formatting truyền thống, có thể được đặt thành "{" cho kiểu :meth:`str.format` mới hoặc có thể được đặt thành "$" cho kiểu định dạng theo shell do
:class:`string.Template` cung cấp. Ba cấu hình sau đây là tương đương::

    >>> from logging import basicConfig
    >>> basicConfig(style='%', format="%(name)s -> %(levelname)s: %(message)s")
    >>> basicConfig(style='{', format="{name} -> {levelname} {message}")
    >>> basicConfig(style='$', format="$name -> $levelname: $message")

Nếu chưa có cấu hình nào được thiết lập trước khi một sự kiện logging xảy ra, hiện đã có một cấu hình mặc định sử dụng :class:`~logging.StreamHandler` hướng đến
:data:`sys.stderr` cho các sự kiện có mức ``WARNING`` trở lên. Trước đây, một sự kiện xảy ra trước khi cấu hình được thiết lập sẽ либо raise exception hoặc bị loại bỏ một cách âm thầm, tùy thuộc vào giá trị của
:data:`logging.raiseExceptions`. Trình xử lý mặc định mới được lưu trong
:data:`logging.lastResort`.

Việc sử dụng các filter đã được đơn giản hóa. Thay vì tạo một
đối tượng :class:`~logging.Filter`, predicate có thể là bất kỳ callable Python nào trả về ``True`` hoặc ``False``.

Một số cải tiến khác đã tăng tính linh hoạt và đơn giản hóa việc cấu hình. Xem tài liệu module để biết danh sách đầy đủ các thay đổi trong Python 3.2.

contextlib
----------

Có một công cụ mới và hơi gây kinh ngạc
:class:`~contextlib.ContextDecorator` hữu ích trong việc tạo một
:term:`context manager` có thể đồng thời hoạt động như một function decorator.

Để thuận tiện, chức năng mới này được sử dụng bởi
:deco:`~contextlib.contextmanager` để không cần thêm nỗ lực nào nhằm hỗ trợ cả hai vai trò.

Ý tưởng cơ bản là cả context manager và function decorator đều có thể được dùng làm wrapper trước hành động và sau hành động. Context manager bọc một nhóm câu lệnh bằng câu lệnh :keyword:`with`, còn function decorator bọc một nhóm câu lệnh được đặt trong một hàm. Vì vậy, đôi khi cần viết một wrapper trước hành động hoặc sau hành động có thể được dùng cho cả hai vai trò.

Ví dụ, đôi khi việc bọc các hàm hoặc nhóm câu lệnh bằng một logger có thể theo dõi thời điểm bắt đầu và kết thúc sẽ rất hữu ích. Thay vì viết cả function decorator và context manager cho tác vụ này,
:deco:`~contextlib.contextmanager` cung cấp cả hai khả năng trong một định nghĩa duy nhất::

    from contextlib import contextmanager
    import logging

    logging.basicConfig(level=logging.INFO)

    @contextmanager
    def track_entry_and_exit(name):
        logging.info('Entering: %s', name)
        yield
        logging.info('Exiting: %s', name)

Trước đây, cách này chỉ có thể được sử dụng như một context manager::

    with track_entry_and_exit('widget loader'):
        print('Some time consuming activity goes here')
        load_widget()

Giờ đây, nó cũng có thể được dùng như một decorator::

    @track_entry_and_exit('widget loader')
    def activity():
        print('Some time consuming activity goes here')
        load_widget()

Việc đảm nhiệm đồng thời hai vai trò đặt ra một số hạn chế cho kỹ thuật này. Context manager thường đủ linh hoạt để trả về một đối số có thể được sử dụng bởi câu lệnh :keyword:`with`, nhưng function decorator không có cơ chế tương đương.

Trong ví dụ trên, không có cách rõ ràng nào để context manager *track_entry_and_exit* trả về một logging instance để sử dụng trong phần thân của các câu lệnh được bao quanh.

(Do Michael Foord đóng góp trong :issue:`9110`.)

decimal và fractions
--------------------

Mark Dickinson đã xây dựng một cơ chế thanh lịch và hiệu quả để đảm bảo rằng các kiểu dữ liệu số khác nhau sẽ có cùng giá trị hash bất cứ khi nào giá trị thực của chúng bằng nhau (:issue:`8188`)::

   assert hash(Fraction(3, 2)) == hash(1.5) == \
          hash(Decimal("1.5")) == hash(complex(1.5, 0))

Một số chi tiết về hashing được cung cấp thông qua một thuộc tính mới,
:data:`sys.hash_info`, mô tả độ rộng bit của giá trị hash, modulus nguyên tố, các giá trị hash cho *infinity* và *nan*, cùng với hệ số nhân được sử dụng cho phần ảo của một số:

>>> sys.hash_info # doctest: +SKIP
sys.hash_info(width=64, modulus=2305843009213693951, inf=314159, nan=0, imag=1000003)

Quyết định ban đầu về việc hạn chế khả năng tương tác giữa các kiểu dữ liệu số khác nhau đã được nới lỏng. Vẫn không hỗ trợ (và không nên sử dụng) việc trộn ngầm trong các biểu thức số học như ``Decimal('1.1') + float('1.1')`` vì kiểu sau sẽ làm mất thông tin trong quá trình tạo binary float. Tuy nhiên, vì các giá trị floating-point hiện có có thể được chuyển đổi không mất mát sang dạng decimal hoặc rational, nên việc thêm chúng vào constructor và hỗ trợ so sánh giữa các kiểu khác nhau là hợp lý.

* Hàm khởi tạo :class:`decimal.Decimal` hiện chấp nhận trực tiếp các đối tượng :class:`float`, nên không còn cần sử dụng phương thức :meth:`~decimal.Decimal.from_float` (:issue:`8257`).

* Các phép so sánh giữa các kiểu khác nhau hiện được hỗ trợ đầy đủ, nhờ đó
  Các đối tượng :class:`~decimal.Decimal` có thể được so sánh trực tiếp với :class:`float` và :class:`fractions.Fraction` (:issue:`2531` và :issue:`8188`).

Những thay đổi tương tự đã được thực hiện đối với :class:`fractions.Fraction` để
các phương thức :meth:`~fractions.Fraction.from_float` và :meth:`~fractions.Fraction.from_decimal` không còn cần thiết (:issue:`8294`):

>>> from decimal import Decimal
>>> from fractions import Fraction
>>> Decimal(1.1)
Decimal('1.100000000000000088817841970012523233890533447265625')
>>> Fraction(1.1)
Fraction(2476979795053773, 2251799813685248)

Một thay đổi hữu ích khác đối với mô-đun :mod:`decimal` là
thuộc tính :attr:`Context.clamp <decimal.Context.clamp>` hiện đã là thuộc tính công khai. Điều này hữu ích khi tạo các context tương ứng với những định dạng trao đổi decimal được quy định trong IEEE 754 (xem :issue:`8540`).

(Đóng góp của Mark Dickinson và Raymond Hettinger.)

gzip và zipfile
---------------

:class:`gzip.GzipFile` hiện đã triển khai :class:`io.BufferedIOBase`
:term:`abstract base class` (ngoại trừ ``truncate()``). Nó cũng có một

>>> len(b)
89
>>> c = gzip.compress(b)
>>> len(c)
77
>>> gzip.decompress(c).decode()[:42]      # decompress and convert to text
'Three shall be the number thou shalt count'

tarfile
-------

Giờ đây, lớp :class:`~tarfile.TarFile` có thể được sử dụng như một context manager. Ngoài ra, phương thức :meth:`~tarfile.TarFile.add` của lớp này có một tùy chọn mới, *filter*, dùng để kiểm soát những tệp nào được thêm vào archive và cho phép chỉnh sửa metadata của tệp.

Tùy chọn *filter* mới thay thế tham số *exclude* cũ, kém linh hoạt hơn và hiện đã bị deprecated. Nếu được chỉ định, tham số *filter* tùy chọn cần phải là một :term:`keyword argument`. Hàm filter do người dùng cung cấp nhận một
:class:`~tarfile.TarInfo` đối tượng và trả về một phiên bản đã cập nhật
:class:`~tarfile.TarInfo` đối tượng, hoặc nếu muốn loại trừ tệp, hàm có thể trả về ``None``::

    >>> import tarfile, glob

    >>> def myfilter(tarinfo):
    ...     if tarinfo.isfile():             # only save real files
    ...         tarinfo.uname = 'monty'      # redact the user name
    ...         return tarinfo

    >>> with tarfile.open(name='myarchive.tar.gz', mode='w:gz') as tf:
    ...     for filename in glob.glob('*.txt'):
    ...         tf.add(filename, filter=myfilter)
    ...     tf.list()
    -rw-r--r-- monty/501        902 2011-01-26 17:59:11 annotations.txt
    -rw-r--r-- monty/501        123 2011-01-26 17:59:11 general_questions.txt
    -rw-r--r-- monty/501       3514 2011-01-26 17:59:11 prion.txt
    -rw-r--r-- monty/501        124 2011-01-26 17:59:11 py_todo.txt
    -rw-r--r-- monty/501       1399 2011-01-26 17:59:11 semaphore_notes.txt

shutil
------

Hàm :func:`shutil.copytree` có hai tùy chọn mới:

* *ignore_dangling_symlinks*: khi ``symlinks=False`` để hàm sao chép tệp mà symlink trỏ tới, thay vì chính symlink đó. Tùy chọn này sẽ loại bỏ lỗi được phát sinh nếu tệp không tồn tại.

  :func:`shutil.copy2` được sử dụng theo mặc định.

(Do Tarek Ziadé đóng góp.)

Ngoài ra, module :mod:`shutil` hiện hỗ trợ :ref:`các thao tác lưu trữ <archiving-operations>` đối với zipfile, tarfile không nén, tarfile nén bằng gzip và tarfile nén bằng bzip2. Ngoài ra còn có các hàm để đăng ký thêm các định dạng file lưu trữ (chẳng hạn như tarfile nén bằng xz hoặc các định dạng tùy chỉnh).

Các hàm chính là :func:`~shutil.make_archive` và
:func:`~shutil.unpack_archive`. Theo mặc định, cả hai đều hoạt động trên thư mục hiện tại (có thể thiết lập bằng :func:`os.chdir`) và mọi thư mục con. Tên file lưu trữ cần được chỉ định bằng đường dẫn đầy đủ. Bước lưu trữ không làm thay đổi dữ liệu (các file gốc được giữ nguyên).

::

    >>> import shutil, pprint

    >>> os.chdir('mydata')  # change to the source directory
    >>> f = shutil.make_archive('/var/backup/mydata',
    ...                         'zip')      # archive the current directory
    >>> f                                   # show the name of archive
    '/var/backup/mydata.zip'
    >>> os.chdir('tmp')                     # change to an unpacking
    >>> shutil.unpack_archive('/var/backup/mydata.zip')  # recover the data

    >>> pprint.pprint(shutil.get_archive_formats())  # display known formats
    [('bztar', "bzip2'ed tar-file"),
     ('gztar', "gzip'ed tar-file"),
     ('tar', 'uncompressed tar file'),
     ('zip', 'ZIP file')]

    >>> shutil.register_archive_format(     # register a new archive format
    ...     name='xz',
    ...     function=xz.compress,           # callable archiving function
    ...     extra_args=[('level', 8)],      # arguments to the function
    ...     description='xz compression'
    ... )

ssl
---

Mô-đun :mod:`ssl` đã bổ sung một số tính năng để đáp ứng các yêu cầu phổ biến đối với kết nối internet an toàn (được mã hóa, xác thực):

* Một lớp mới, :class:`~ssl.SSLContext`, đóng vai trò là vùng chứa cho dữ liệu SSL liên tục, chẳng hạn như các thiết lập giao thức, chứng chỉ, khóa riêng tư và nhiều tùy chọn khác. Lớp này bao gồm một :meth:`~ssl.SSLContext.wrap_socket` để tạo socket SSL từ ngữ cảnh SSL.

* Một hàm mới, :func:`!ssl.match_hostname`, hỗ trợ xác minh danh tính máy chủ cho các giao thức cấp cao hơn bằng cách triển khai các quy tắc của HTTPS (từ :rfc:`2818`), vốn cũng phù hợp với các giao thức khác.

* Hàm khởi tạo :func:`ssl.wrap_socket() <ssl.SSLContext.wrap_socket>` hiện nhận một đối số *ciphers*. Chuỗi *ciphers* liệt kê các thuật toán mã hóa được phép theo định dạng được mô tả trong `tài liệu OpenSSL <https://docs.openssl.org/1.0.2/man1/ciphers/#cipher-list-format>`__.

* Khi được liên kết với các phiên bản OpenSSL gần đây, module :mod:`ssl` hiện hỗ trợ phần mở rộng Server Name Indication của giao thức TLS, cho phép nhiều "virtual host" sử dụng các chứng chỉ khác nhau trên cùng một cổng IP. Phần mở rộng này chỉ được hỗ trợ ở chế độ client và được kích hoạt bằng cách truyền đối số *server_hostname* cho :meth:`ssl.SSLContext.wrap_socket`.

* Nhiều tùy chọn đã được thêm vào module :mod:`ssl`, chẳng hạn như
  :data:`~ssl.OP_NO_SSLv2`, tùy chọn này vô hiệu hóa giao thức SSLv2 không an toàn và đã lỗi thời.

* Phần mở rộng hiện tải tất cả các cipher và thuật toán digest của OpenSSL. Nếu không thể xác minh một số chứng chỉ SSL, chúng sẽ được báo cáo với lỗi "unknown algorithm".

* Phiên bản OpenSSL đang được sử dụng hiện có thể được truy cập bằng thuộc tính module :const:`ssl.OPENSSL_VERSION` (một chuỗi),
  :const:`ssl.OPENSSL_VERSION_INFO` (một tuple gồm 5 phần tử), và
  :const:`ssl.OPENSSL_VERSION_NUMBER` (một số nguyên).

(Đóng góp của Antoine Pitrou trong :issue:`8850`, :issue:`1589`, :issue:`8322`,
:issue:`5639`, :issue:`4870`, :issue:`8484`, và :issue:`8321`.)

http.client
-----------

Có một số cải tiến nhỏ về API trong module :mod:`http.client`. Các phản hồi đơn giản HTTP 0.9 kiểu cũ không còn được hỗ trợ và tham số *strict* đã bị deprecated trong tất cả các lớp.

Các :class:`~http.client.HTTPConnection` và
Các lớp :class:`~http.client.HTTPSConnection` hiện có tham số *source_address* cho một tuple (host, port), cho biết kết nối HTTP được thiết lập từ đâu.

Hỗ trợ kiểm tra chứng chỉ và virtual host HTTPS đã được thêm vào
:class:`~http.client.HTTPSConnection`.

Phương thức :meth:`~http.client.HTTPConnection.request` trên các đối tượng connection cho phép một đối số *body* tùy chọn để có thể dùng một :term:`file object` cung cấp nội dung của request. Thuận tiện hơn, đối số *body* hiện cũng chấp nhận một đối tượng :term:`iterable` miễn là đối tượng đó có header ``Content-Length`` rõ ràng. Interface mở rộng này linh hoạt hơn nhiều so với trước đây.

Để thiết lập kết nối HTTPS thông qua máy chủ proxy, có một
phương thức :meth:`~http.client.HTTPConnection.set_tunnel` mới để thiết lập host và port cho việc tunneling HTTP Connect.

Để khớp với hành vi của :mod:`http.server`, thư viện HTTP client hiện cũng mã hóa các header bằng encoding ISO-8859-1 (Latin-1). Trước đây, thư viện đã thực hiện việc này đối với các header đến, vì vậy hiện hành vi đã nhất quán cho cả lưu lượng đến và đi. (Xem công trình của Armin Ronacher trong :issue:`10980`.)

unittest
--------

Module unittest có một số cải tiến hỗ trợ việc discovery test cho các package, giúp thử nghiệm dễ dàng hơn tại interactive prompt, bổ sung các phương thức testcase mới, cải thiện thông báo chẩn đoán cho các test bị lỗi và đặt tên phương thức tốt hơn.

* Lệnh gọi dòng lệnh ``python -m unittest`` hiện có thể chấp nhận các đường dẫn tệp thay vì tên module để chạy các test cụ thể (:issue:`10620`). Tính năng test discovery mới có thể tìm các test bên trong package, xác định mọi test có thể import từ thư mục cấp cao nhất. Có thể chỉ định thư mục cấp cao nhất bằng tùy chọn ``-t``, một mẫu để khớp các tệp bằng ``-p``, và một thư mục để bắt đầu discovery bằng ``-s``:

  .. code-block:: shell-session

    $ python -m unittest discover -s my_proj_dir -p _test.py

  (Đóng góp của Michael Foord.)

* Việc thử nghiệm tại dấu nhắc tương tác giờ đây dễ dàng hơn vì
  :class:`unittest.TestCase` class giờ đây có thể được khởi tạo mà không cần đối số:

  >>> from unittest import TestCase
  >>> TestCase().assertEqual(pow(2, 3), 8)

  (Đóng góp của Michael Foord.)

* :mod:`unittest` module có hai phương thức mới là
  :meth:`~unittest.TestCase.assertWarns` và
  :meth:`~unittest.TestCase.assertWarnsRegex` để xác minh rằng một loại cảnh báo nhất định được kích hoạt bởi mã đang được kiểm thử::

      with self.assertWarns(DeprecationWarning):
          legacy_function('XYZ')

  (Đóng góp của Antoine Pitrou, :issue:`9754`.)

  Một phương thức mới khác, :meth:`~unittest.TestCase.assertCountEqual` được dùng để so sánh hai iterable nhằm xác định xem số lượng phần tử của chúng có bằng nhau hay không (tức là có cùng các phần tử với cùng số lần xuất hiện, bất kể thứ tự)::

     def test_anagram(self):
         self.assertCountEqual('algorithm', 'logarithm')

  (Do Raymond Hettinger đóng góp.)

* Một tính năng chính của module unittest là nỗ lực tạo ra thông tin chẩn đoán có ý nghĩa khi một test thất bại. Khi có thể, lỗi sẽ được ghi lại cùng với diff của đầu ra. Điều này đặc biệt hữu ích khi phân tích các tệp log của những lần chạy test thất bại. Tuy nhiên, vì diff đôi khi có thể rất dài, một thuộc tính :attr:`~unittest.TestCase.maxDiff` mới được bổ sung để đặt độ dài tối đa của diff được hiển thị.

* Ngoài ra, tên các phương thức trong module đã được chỉnh sửa và làm gọn ở một số điểm.

  Ví dụ: :meth:`~unittest.TestCase.assertRegex` là tên mới của
  :meth:`!assertRegexpMatches`, tên trước đây không chính xác vì test sử dụng :func:`re.search`, chứ không phải :func:`re.match`. Các phương thức khác sử dụng biểu thức chính quy hiện được đặt tên bằng dạng ngắn "Regex" thay vì "Regexp" -- điều này phù hợp với tên được dùng trong các triển khai unittest khác, phù hợp với tên cũ của Python cho module :mod:`re`, đồng thời có cách viết camel-case không mơ hồ.

  (Do Raymond Hettinger đóng góp và Ezio Melotti triển khai.)

* Để cải thiện tính nhất quán, một số bí danh phương thức đã tồn tại từ lâu đang bị loại bỏ để ưu tiên các tên được khuyến nghị:

   +--------------------------------+-------------------------------+
   | Tên cũ                         | Tên được khuyến nghị          |
   +================================+===============================+
   | :meth:`!assert_`               | :meth:`.assertTrue`           |
   +--------------------------------+-------------------------------+
   | :meth:`!assertEquals`          | :meth:`.assertEqual`          |
   +--------------------------------+-------------------------------+
   | :meth:`!assertNotEquals`       | :meth:`.assertNotEqual`       |
   +--------------------------------+-------------------------------+
   | :meth:`!assertAlmostEquals`    | :meth:`.assertAlmostEqual`    |
   +--------------------------------+-------------------------------+
   | :meth:`!assertNotAlmostEquals` | :meth:`.assertNotAlmostEqual` |
   +--------------------------------+-------------------------------+

  Tương tự, các phương thức ``TestCase.fail*`` không còn được khuyến nghị trong Python 3.1 dự kiến sẽ bị loại bỏ trong Python 3.3.

  (Do Ezio Melotti đóng góp; :issue:`9424`.)

* Phương thức :meth:`!assertDictContainsSubset` không còn được khuyến nghị vì được triển khai sai với các đối số không đúng thứ tự. Điều này tạo ra những ảo giác quang học khó gỡ lỗi, trong đó các kiểm thử như ``TestCase().assertDictContainsSubset({'a':1, 'b':2}, {'a':1})`` sẽ thất bại.

  (Do Raymond Hettinger đóng góp.)

site
----

Mô-đun :mod:`site` có ba hàm mới hữu ích để báo cáo chi tiết về một bản cài đặt Python nhất định.

sysconfig
---------

Mô-đun :mod:`sysconfig` mới giúp dễ dàng tìm ra các đường dẫn cài đặt và biến cấu hình thay đổi tùy theo nền tảng và cách cài đặt.

Mô-đun cung cấp các hàm truy cập đơn giản để lấy thông tin về nền tảng và phiên bản:

* :func:`~sysconfig.get_platform` trả về các giá trị như *linux-i586* hoặc *macosx-10.6-ppc*.
* :func:`~sysconfig.get_python_version` trả về một chuỗi phiên bản Python, chẳng hạn như "3.2".

Mô-đun cũng cung cấp quyền truy cập vào các đường dẫn và biến tương ứng với một trong bảy scheme có tên được ``distutils`` sử dụng. Các scheme đó gồm *posix_prefix*, *posix_home*, *posix_user*, *nt*, *nt_user*, *os2*, *os2_home*:

* :func:`~sysconfig.get_paths` tạo một dictionary chứa các đường dẫn cài đặt cho scheme cài đặt hiện tại.
* :func:`~sysconfig.get_config_vars` trả về một dictionary gồm các biến dành riêng cho nền tảng.

Ngoài ra còn có một giao diện dòng lệnh tiện dụng:

.. code-block:: doscon

  C:\Python32>python -m sysconfig
  Platform: "win32"
  Python version: "3.2"
  Current installation scheme: "nt"

pdb
---

Mô-đun debugger :mod:`pdb` đã có thêm một số cải tiến về khả năng sử dụng:

* :file:`pdb.py` hiện có tùy chọn ``-c`` để thực thi các lệnh như được cung cấp trong một
  Tệp script :file:`.pdbrc`.

* Lệnh mới: ``interact`` để khởi động một trình thông dịch tương tác chứa các tên toàn cục và cục bộ được tìm thấy trong phạm vi hiện tại.

configparser
------------

Mô-đun :mod:`configparser` đã được sửa đổi để cải thiện tính dễ sử dụng và khả năng dự đoán của parser mặc định cùng cú pháp INI được hỗ trợ. Phiên bản cũ
:class:`!ConfigParser` đã bị xóa để thay thế bằng :class:`!SafeConfigParser`, sau đó được đổi tên thành :class:`~configparser.ConfigParser`. Việc hỗ trợ comment nội dòng hiện đã được tắt theo mặc định và không cho phép trùng lặp section hoặc option trong cùng một nguồn cấu hình.

Các parser cấu hình được bổ sung API mới dựa trên mapping protocol::

    >>> parser = ConfigParser()
    >>> parser.read_string("""
    ... [DEFAULT]
    ... location = upper left
    ... visible = yes
    ... editable = no
    ... color = blue
    ...
    ... [main]
    ... title = Main Menu
    ... color = green
    ...
    ... [options]
    ... title = Options
    ... """)
    >>> parser['main']['color']
    'green'
    >>> parser['main']['editable']
    'no'
    >>> section = parser['options']
    >>> section['title']
    'Options'
    >>> section['title'] = 'Options (editable: %(editable)s)'
    >>> section['title']
    'Options (editable: no)'

API mới được triển khai dựa trên API truyền thống, vì vậy các subclass parser tùy chỉnh có thể sử dụng API này mà không cần sửa đổi.

Cấu trúc tệp INI được các parser cấu hình chấp nhận giờ đây có thể được tùy chỉnh. Người dùng có thể chỉ định các dấu phân cách option/value và tiền tố comment thay thế, thay đổi tên của section *DEFAULT* hoặc chuyển sang cú pháp interpolation khác.

Có hỗ trợ interpolation có thể cắm thêm, bao gồm một trình xử lý interpolation bổ sung :class:`~configparser.ExtendedInterpolation`::

  >>> parser = ConfigParser(interpolation=ExtendedInterpolation())
  >>> parser.read_dict({'buildout': {'directory': '/home/ambv/zope9'},
  ...                   'custom': {'prefix': '/usr/local'}})
  >>> parser.read_string("""
  ... [buildout]
  ... parts =
  ...   zope9
  ...   instance
  ... find-links =
  ...   ${buildout:directory}/downloads/dist
  ...
  ... [zope9]
  ... recipe = plone.recipe.zope9install
  ... location = /opt/zope
  ...
  ... [instance]
  ... recipe = plone.recipe.zope9instance
  ... zope9-location = ${zope9:location}
  ... zope-conf = ${custom:prefix}/etc/zope.conf
  ... """)
  >>> parser['buildout']['find-links']
  '\n/home/ambv/zope9/downloads/dist'
  >>> parser['instance']['zope-conf']
  '/usr/local/etc/zope.conf'
  >>> instance = parser['instance']
  >>> instance['zope-conf']
  '/usr/local/etc/zope.conf'
  >>> instance['zope9-location']
  '/opt/zope'

Một số tính năng nhỏ hơn cũng được giới thiệu, chẳng hạn như hỗ trợ chỉ định encoding trong các thao tác đọc, chỉ định giá trị dự phòng cho các hàm get hoặc đọc trực tiếp từ các dictionary và chuỗi.

(Tất cả thay đổi đều do Łukasz Langa đóng góp.)

urllib.parse
------------

Một số cải tiến về khả năng sử dụng đã được thực hiện cho module :mod:`urllib.parse`.

Hàm :func:`~urllib.parse.urlparse` giờ đây hỗ trợ các địa chỉ `IPv6 <https://en.wikipedia.org/wiki/IPv6>`_ như được mô tả trong :rfc:`2732`:

    >>> import urllib.parse
    >>> urllib.parse.urlparse('http://[dead:beef:cafe:5417:affe:8FA3:deaf:feed]/foo/') # doctest: +NORMALIZE_WHITESPACE
    ParseResult(scheme='http',
                netloc='[dead:beef:cafe:5417:affe:8FA3:deaf:feed]',
                path='/foo/',
                params='',
                query='',
                fragment='')

Hàm :func:`~urllib.parse.urldefrag` giờ đây trả về một :term:`named tuple`::

    >>> r = urllib.parse.urldefrag('http://python.org/about/#target')
    >>> r
    DefragResult(url='http://python.org/about/', fragment='target')
    >>> r[0]
    'http://python.org/about/'
    >>> r.fragment
    'target'

Ngoài ra, hàm :func:`~urllib.parse.urlencode` hiện linh hoạt hơn nhiều, chấp nhận đối số *query* có kiểu string hoặc bytes. Nếu là string, các tham số *safe*, *encoding* và *error* sẽ được truyền tới
:func:`~urllib.parse.quote_plus` để mã hóa::

    >>> urllib.parse.urlencode([
    ...      ('type', 'telenovela'),
    ...      ('name', '¿Dónde Está Elisa?')],
    ...      encoding='latin-1')
    'type=telenovela&name=%BFD%F3nde+Est%E1+Elisa%3F'

Như đã trình bày chi tiết trong :ref:`parsing-ascii-encoded-bytes`, tất cả các hàm :mod:`urllib.parse` hiện đều chấp nhận chuỗi byte được mã hóa ASCII làm đầu vào, miễn là chúng không được trộn với các string thông thường. Nếu các chuỗi byte được mã hóa ASCII được cung cấp làm tham số, kiểu trả về cũng sẽ là chuỗi byte được mã hóa ASCII:

    >>> urllib.parse.urlparse(b'http://www.python.org:80/about/') # doctest: +NORMALIZE_WHITESPACE
    ParseResultBytes(scheme=b'http', netloc=b'www.python.org:80',
                     path=b'/about/', params=b'', query=b'', fragment=b'')

(Thực hiện bởi Nick Coghlan, Dan Mahn và Senthil Kumaran trong :issue:`2987`,
:issue:`5468` và :issue:`9873`.)

mailbox
-------

Nhờ nỗ lực phối hợp của R. David Murray, module :mod:`mailbox` đã được sửa cho Python 3.2. Thách thức là mailbox vốn được thiết kế ban đầu với giao diện văn bản, nhưng các thông điệp email được biểu diễn tốt nhất bằng
:class:`bytes` vì các phần khác nhau của một message có thể sử dụng các encoding khác nhau.

Giải pháp này tận dụng khả năng hỗ trợ dữ liệu nhị phân của package :mod:`email` để phân tích cú pháp các email message tùy ý. Ngoài ra, giải pháp còn yêu cầu một số thay đổi đối với API.

Đúng như dự kiến, phương thức :meth:`~mailbox.Mailbox.add` dành cho
các đối tượng :class:`mailbox.Mailbox` hiện chấp nhận đầu vào nhị phân.

:class:`~io.StringIO` và đầu vào tệp văn bản đã bị deprecated. Ngoài ra, đầu vào chuỗi sẽ báo lỗi sớm nếu sử dụng các ký tự không phải ASCII. Trước đây, lỗi chỉ xảy ra khi email được xử lý ở một bước sau đó.

Đầu ra nhị phân cũng được hỗ trợ. Phương thức :meth:`~mailbox.Mailbox.get_file` hiện trả về một tệp ở chế độ nhị phân (trước đây phương thức này đã đặt sai tệp ở chế độ văn bản). Ngoài ra còn có một phương thức :meth:`~mailbox.Mailbox.get_bytes` mới, trả về biểu diễn :class:`bytes` của một message tương ứng với *key* đã cho.

Bạn vẫn có thể nhận đầu ra không phải nhị phân bằng API cũ
phương thức :meth:`~mailbox.Mailbox.get_string`, nhưng cách tiếp cận đó không hữu ích lắm. Thay vào đó, tốt nhất là trích xuất các message từ một đối tượng :class:`~mailbox.Message` hoặc tải chúng từ đầu vào nhị phân.

(Đóng góp bởi R. David Murray, cùng với nỗ lực của Steffen Daode Nurpmeso và bản vá ban đầu của Victor Stinner trong :issue:`9124`.)

Đa luồng
========

* Cơ chế tuần tự hóa việc thực thi các thread Python chạy đồng thời (thường được gọi là :term:`GIL` hoặc Global Interpreter Lock) đã được viết lại. Các mục tiêu bao gồm khoảng thời gian chuyển đổi dễ dự đoán hơn và giảm overhead do tranh chấp lock cũng như số lượng system call phát sinh. Khái niệm về "khoảng thời gian kiểm tra" để cho phép chuyển đổi giữa các thread đã bị loại bỏ và được thay thế bằng một khoảng thời gian tuyệt đối, tính bằng giây. Tham số này có thể được điều chỉnh thông qua :func:`sys.setswitchinterval`. Hiện tại, giá trị mặc định là 5 mili giây.

  Có thể đọc thêm thông tin chi tiết về quá trình triển khai trong `thông báo trên danh sách thư python-dev <https://mail.python.org/pipermail/python-dev/2009-October/093321.html>`_ (tuy nhiên, các "yêu cầu về mức độ ưu tiên" được nêu trong thông báo này đã không được giữ lại để đưa vào).

  (Đóng góp của Antoine Pitrou.)

* Các khóa thông thường và đệ quy hiện chấp nhận đối số *timeout* tùy chọn cho phương thức của chúng
  phương thức :meth:`~threading.Lock.acquire`.  (Đóng góp của Antoine Pitrou;
  :issue:`7316`.)

* Tương tự, :meth:`threading.Semaphore.acquire` cũng có thêm đối số *timeout*.  (Đóng góp của Torsten Landschoff; :issue:`850728`.)

* Giờ đây, việc lấy khóa thông thường và khóa đệ quy có thể bị gián đoạn bởi các tín hiệu trên những nền tảng sử dụng Pthreads. Điều này có nghĩa là các chương trình Python bị deadlock trong khi lấy khóa có thể được kết thúc thành công bằng cách liên tục gửi SIGINT đến tiến trình (bằng cách nhấn :kbd:`Ctrl+C` trong hầu hết các shell). (Đóng góp của Reid Kleckner; :issue:`8844`.)


Tối ưu hóa
==========

Một số cải tiến nhỏ về hiệu năng đã được bổ sung:

* Trình tối ưu peephole của Python hiện nhận ra các mẫu như ``x in {1, 2, 3}`` là phép kiểm tra phần tử có thuộc một tập hợp các hằng số hay không. Trình tối ưu chuyển đổi
  :class:`set` thành một :class:`frozenset` và lưu trữ hằng số được tạo sẵn.

  Giờ đây, khi không còn bị phạt về tốc độ, việc bắt đầu viết các phép kiểm tra phần tử bằng ký hiệu tập hợp trở nên thiết thực. Cách viết này vừa rõ ràng về mặt ngữ nghĩa vừa nhanh về mặt thực thi::

      extension = name.rpartition('.')[2]
      if extension in {'xml', 'html', 'xhtml', 'css'}:
          handle(name)

  (Bản vá và các bài kiểm thử bổ sung do Dave Malcolm đóng góp; :issue:`6690`).

* Việc tuần tự hóa và giải tuần tự hóa dữ liệu bằng module :mod:`pickle` hiện nhanh hơn vài lần.

  (Do Alexandre Vassalotti, Antoine Pitrou và nhóm Unladen Swallow đóng góp trong :issue:`9410` và :issue:`3873`.)

* Thuật toán `Timsort <https://en.wikipedia.org/wiki/Timsort>`_ được sử dụng trong
  :meth:`list.sort` và :func:`sorted` hiện chạy nhanh hơn và sử dụng ít bộ nhớ hơn khi được gọi với một :term:`key function`. Trước đây, mỗi phần tử của danh sách được bọc trong một đối tượng tạm thời ghi nhớ giá trị khóa liên kết với từng phần tử. Hiện nay, hai mảng khóa và giá trị được sắp xếp song song. Điều này giúp tiết kiệm bộ nhớ vốn được các lớp bọc phục vụ việc sắp xếp sử dụng, đồng thời giảm thời gian bị tiêu tốn cho việc ủy quyền so sánh.

  (Bản vá do Daniel Stutzbach đóng góp trong :issue:`9915`.)

* Hiệu năng giải mã JSON được cải thiện và mức tiêu thụ bộ nhớ giảm bất cứ khi nào cùng một chuỗi được lặp lại cho nhiều khóa. Ngoài ra, việc mã hóa JSON hiện sử dụng các tối ưu hóa tốc độ bằng C khi đối số ``sort_keys`` là true.

  (Do Antoine Pitrou đóng góp trong :issue:`7451`, và Raymond Hettinger cùng Antoine Pitrou đóng góp trong :issue:`10314`.)

* Các khóa đệ quy (được tạo bằng API :func:`threading.RLock`) hiện được hưởng lợi từ một triển khai bằng C, giúp chúng nhanh ngang các khóa thông thường và nhanh hơn từ 10 đến 15 lần so với triển khai Python thuần túy trước đây.

  (Do Antoine Pitrou đóng góp; :issue:`3001`.)

* Thuật toán tìm kiếm nhanh trong stringlib hiện được sử dụng bởi :meth:`~str.split`,
  các phương thức :meth:`~str.rsplit`, :meth:`~str.splitlines` và :meth:`~str.replace` trên
  các đối tượng :class:`bytes`, :class:`bytearray` và :class:`str`. Tương tự, thuật toán này cũng được sử dụng bởi :meth:`~str.rfind`, :meth:`~str.rindex`, :meth:`~str.rsplit` và
  :meth:`~str.rpartition`.

  (Bản vá của Florent Xicluna trong :issue:`7622` và :issue:`7462`.)


* Giờ đây, việc chuyển đổi số nguyên thành chuỗi xử lý hai "chữ số" mỗi lần, làm giảm số phép chia và phép modulo.

  (:issue:`6713` của Gawain Bolton, Mark Dickinson và Victor Stinner.)

Một số tối ưu hóa nhỏ khác cũng đã được thực hiện. Phép lấy hiệu hai tập hợp giờ đây chạy nhanh hơn khi một toán hạng lớn hơn nhiều so với toán hạng kia (bản vá của Andress Bennetts trong
:issue:`8685`). Phương thức :meth:`!array.repeat` có cách triển khai nhanh hơn (:issue:`1569291` của Alexander Belopolsky). :class:`~http.server.BaseHTTPRequestHandler` có cơ chế buffering hiệu quả hơn (:issue:`3709` của Andrew Schaaf).
Hàm :func:`operator.attrgetter` đã được tăng tốc (:issue:`10160` của Christos Georgiou). Và :class:`~configparser.ConfigParser` tải các đối số nhiều dòng nhanh hơn một chút (:issue:`7113` của Łukasz Langa).


Unicode
=======

Python đã được cập nhật lên `Unicode 6.0.0 <https://unicode.org/versions/Unicode6.0.0/>`_. Bản cập nhật tiêu chuẩn này bổ sung hơn 2.000 ký tự mới, bao gồm các biểu tượng `emoji <https://en.wikipedia.org/wiki/Emoji>`_, vốn rất quan trọng đối với điện thoại di động.

Ngoài ra, tiêu chuẩn được cập nhật đã thay đổi thuộc tính ký tự của hai ký tự Kannada (U+0CF1, U+0CF2) và một ký tự số New Tai Lue (U+19DA), khiến hai ký tự đầu đủ điều kiện được sử dụng trong các identifier, trong khi ký tự sau không còn đủ điều kiện. Để biết thêm thông tin, hãy xem `Unicode Character Database Changes <https://www.unicode.org/versions/Unicode6.0.0/#Database_Changes>`_.


Codecs
======

Đã bổ sung hỗ trợ cho *cp720*, một encoding Arabic DOS (:issue:`1616979`).

Mã hóa MBCS không còn bỏ qua đối số trình xử lý lỗi. Ở chế độ strict mặc định, mã hóa này phát sinh :exc:`UnicodeDecodeError` khi gặp một chuỗi byte không thể giải mã và :exc:`UnicodeEncodeError` đối với một ký tự không thể mã hóa.

Codec MBCS hỗ trợ các trình xử lý lỗi ``'strict'`` và ``'ignore'`` để giải mã, cùng ``'strict'`` và ``'replace'`` để mã hóa.

Để mô phỏng mã hóa MBCS của Python3.1, hãy chọn trình xử lý ``'ignore'`` để giải mã và trình xử lý ``'replace'`` để mã hóa.

Trên Mac OS X, Python giải mã các đối số dòng lệnh bằng ``'utf-8'`` thay vì encoding của locale.

Theo mặc định, :mod:`tarfile` sử dụng encoding ``'utf-8'`` trên Windows (thay vì ``'mbcs'``) và trình xử lý lỗi ``'surrogateescape'`` trên tất cả các hệ điều hành.


Tài liệu
========

Tài liệu tiếp tục được cải thiện.

* Một bảng liên kết nhanh đã được thêm vào đầu các phần dài, chẳng hạn như
  :ref:`built-in-funcs`.  Trong trường hợp của :mod:`itertools`, các liên kết đi kèm với những bảng tóm tắt theo kiểu cheat sheet nhằm cung cấp cái nhìn tổng quan và giúp gợi nhớ mà không cần đọc toàn bộ tài liệu.

* Trong một số trường hợp, mã nguồn Python thuần có thể là phần bổ trợ hữu ích cho tài liệu, vì vậy hiện nay nhiều module có các liên kết nhanh đến phiên bản mã nguồn mới nhất.  Ví dụ: tài liệu về module :mod:`functools` có một liên kết nhanh ở đầu với nhãn:

    **Source code** :source:`Lib/functools.py`.

  (Do Raymond Hettinger đóng góp; xem `rationale <https://rhettinger.wordpress.com/2011/01/28/open-your-source-more/>`_.)

* Tài liệu hiện có thêm nhiều ví dụ và recipe hơn.  Cụ thể, module :mod:`re` có một phần mở rộng, :ref:`re-examples`.  Tương tự,
  module :mod:`itertools` tiếp tục được cập nhật với các nội dung mới
  :ref:`itertools-recipes`.

* Mô-đun :mod:`datetime` hiện có thêm một bản triển khai phụ bằng Python thuần. Không có chức năng nào bị thay đổi. Bản triển khai thay thế này giúp mã dễ đọc hơn.

  (Do Alexander Belopolsky đóng góp trong :issue:`9528`.)

* Thư mục :file:`Demo` không còn được duy trì đã bị xóa. Một số bản demo đã được tích hợp vào tài liệu, một số được chuyển sang thư mục :file:`Tools/demo`, còn những bản khác bị xóa hoàn toàn.

  (Do Georg Brandl đóng góp trong :issue:`7962`.)

Kho mã nguồn
============

Ngoài kho mã nguồn Subversion hiện có tại https://svn.python.org, hiện đã có một kho `Mercurial <https://www.mercurial-scm.org/>`_ tại https://hg.python.org/\ .

Sau bản phát hành 3.2, dự kiến sẽ chuyển sang Mercurial làm kho chính. Hệ thống kiểm soát phiên bản phân tán này sẽ giúp các thành viên trong cộng đồng dễ dàng tạo và chia sẻ các changeset bên ngoài hơn. Xem
:pep:`385` để biết chi tiết.

Để tìm hiểu cách sử dụng hệ thống kiểm soát phiên bản mới, hãy xem `Bắt đầu nhanh <https://www.mercurial-scm.org/wiki/QuickStart>`_ hoặc `Hướng dẫn về quy trình làm việc với Mercurial <https://www.mercurial-scm.org/guide>`_.


Thay đổi về build và C API
==========================

Các thay đổi đối với quy trình build của Python và C API bao gồm:

* Các script *idle*, *pydoc* và *2to3* hiện được cài đặt với hậu tố dành riêng cho từng phiên bản trên ``make altinstall`` (:issue:`10679`).

* Các hàm C truy cập Unicode Database hiện chấp nhận và trả về các ký tự thuộc toàn bộ phạm vi Unicode, ngay cả trên các bản build Unicode hẹp (Py_UNICODE_TOLOWER, Py_UNICODE_ISDECIMAL và các hàm khác). Một điểm khác biệt có thể thấy trong Python là :func:`unicodedata.numeric` hiện trả về giá trị chính xác cho các code point lớn, và :func:`repr` có thể xem nhiều ký tự hơn là có thể in được.

  (Do Bupjoe Lee báo cáo và Amaury Forgeot D'Arc sửa; :issue:`5127`.)

* Computed gotos hiện được bật theo mặc định trên các compiler được hỗ trợ (được configure script phát hiện). Bạn vẫn có thể tắt chúng riêng lẻ bằng cách chỉ định ``--without-computed-gotos``.

  (Do Antoine Pitrou đóng góp; :issue:`9203`.)

* Tùy chọn ``--with-wctype-functions`` đã bị loại bỏ. Cơ sở dữ liệu unicode tích hợp hiện được sử dụng cho tất cả các hàm.

  (Do Amaury Forgeot D'Arc đóng góp; :issue:`9210`.)

* Các giá trị hash hiện là các giá trị thuộc một kiểu mới, :c:type:`Py_hash_t`, được định nghĩa có cùng kích thước với một con trỏ. Trước đây, chúng có kiểu long, mà trên một số hệ điều hành 64-bit vẫn chỉ dài 32 bit. Nhờ bản sửa lỗi này, :class:`set` và :class:`dict` hiện có thể chứa nhiều hơn ``2**32`` mục trên các bản build có con trỏ 64-bit (trước đây, chúng có thể tăng đến kích thước đó nhưng hiệu năng suy giảm nghiêm trọng).

  (Do Raymond Hettinger đề xuất và Benjamin Peterson triển khai;
  :issue:`9778`.)

* Một macro mới :c:macro:`!Py_VA_COPY` sao chép trạng thái của danh sách đối số biến thiên. Macro này tương đương với *va_copy* của C99 nhưng có sẵn trên mọi nền tảng Python (:issue:`2443`).

* Một hàm C API mới :c:func:`!PySys_SetArgvEx` cho phép trình thông dịch nhúng thiết lập :data:`sys.argv` mà không đồng thời sửa đổi :data:`sys.path` (:issue:`5753`).

* :c:func:`!PyEval_CallObject` hiện chỉ có sẵn dưới dạng macro. Khai báo hàm, vốn được giữ lại vì lý do tương thích ngược, nay đã bị loại bỏ -- macro này được giới thiệu vào năm 1997 (:issue:`8276`).

* Có một hàm mới :c:func:`PyLong_AsLongLongAndOverflow` tương tự :c:func:`PyLong_AsLongAndOverflow`. Cả hai đều dùng để chuyển đổi :class:`int` của Python thành một kiểu có độ rộng cố định gốc, đồng thời phát hiện các trường hợp không thể chứa vừa giá trị chuyển đổi (:issue:`7767`).

* Hàm :c:func:`PyUnicode_CompareWithASCIIString` hiện trả về *not equal* nếu chuỗi Python được kết thúc bằng *NUL*.

* Có một hàm mới :c:func:`PyErr_NewExceptionWithDoc` tương tự :c:func:`PyErr_NewException` nhưng cho phép chỉ định docstring. Nhờ đó, các ngoại lệ C có khả năng tự mô tả giống như các đối tượng tương ứng thuần Python (:issue:`7033`).

* Khi được biên dịch với tùy chọn ``--with-valgrind``, bộ cấp phát pymalloc sẽ tự động bị vô hiệu hóa khi chạy dưới Valgrind. Điều này giúp phát hiện rò rỉ bộ nhớ tốt hơn khi chạy dưới Valgrind, đồng thời vẫn tận dụng được pymalloc vào những thời điểm khác (:issue:`2422`).

* Đã loại bỏ định dạng ``O?`` khỏi các hàm *PyArg_Parse*. Định dạng này không còn được sử dụng và trước đây cũng chưa từng được tài liệu hóa (:issue:`8837`).

Ngoài ra, còn có một số thay đổi nhỏ khác đối với C-API. Xem tệp `Misc/NEWS <https://github.com/python/cpython/blob/v3.2.6/Misc/NEWS>`__ để biết danh sách đầy đủ.

Ngoài ra, bản build trên Mac OS X cũng có một số cập nhật; xem `Mac/BuildScript/README.txt <https://github.com/python/cpython/blob/v3.2.6/Mac/BuildScript/README.txt>`_ để biết chi tiết. Đối với người dùng chạy bản build 32/64-bit, có một sự cố đã biết với Tcl/Tk mặc định trên Mac OS X 10.6. Vì vậy, chúng tôi khuyến nghị cài đặt một phiên bản thay thế đã cập nhật, chẳng hạn như `ActiveState Tcl/Tk 8.5.9 <https://web.archive.org/web/20101208191259/https://www.activestate.com/activetcl/downloads>`_\. Xem https://www.python.org/download/mac/tcltk/ để biết thêm chi tiết.

Chuyển sang Python 3.2
======================

Phần này liệt kê những thay đổi đã được mô tả trước đó và các bản sửa lỗi khác có thể yêu cầu bạn thay đổi mã của mình:

* Mô-đun :mod:`configparser` đã được dọn dẹp ở một số điểm. Thay đổi chính là thay thế lớp :class:`!ConfigParser` cũ bằng lựa chọn thay thế được ưu tiên từ lâu là :class:`!SafeConfigParser`. Ngoài ra còn có một số điểm không tương thích nhỏ hơn:

  * Cú pháp nội suy hiện được xác thực trên
    :meth:`~configparser.ConfigParser.get` và
    các thao tác :meth:`~configparser.ConfigParser.set`. Trong cơ chế nội suy mặc định, chỉ có hai token chứa dấu phần trăm là ``%(name)s`` và ``%%``, trong đó token sau là dấu phần trăm được escape.

  * :meth:`~configparser.ConfigParser.set` và
    Các phương thức :meth:`~configparser.ConfigParser.add_section` giờ đây xác minh rằng các giá trị thực sự là chuỗi. Trước đây, những kiểu không được hỗ trợ có thể vô tình được đưa vào.

  * Các section hoặc option trùng lặp từ cùng một nguồn giờ đây sẽ gây ra một trong các lỗi sau:
    :exc:`~configparser.DuplicateSectionError` hoặc
    :exc:`~configparser.DuplicateOptionError`. Trước đây, các mục trùng lặp sẽ âm thầm ghi đè lên mục nhập trước đó.

  * Giờ đây, comment nội dòng bị tắt theo mặc định, vì vậy ký tự **;** có thể được sử dụng an toàn trong các giá trị.

  * Giờ đây, comment có thể được thụt lề. Do đó, để **;** hoặc **#** xuất hiện ở đầu một dòng trong các giá trị nhiều dòng, ký tự đó phải được nội suy. Điều này giúp các ký tự tiền tố comment trong giá trị không bị nhầm là comment.

  * ``""`` giờ đây là một giá trị hợp lệ và không còn tự động được chuyển thành chuỗi rỗng. Đối với chuỗi rỗng, hãy sử dụng ``"option ="`` trên một dòng.

* Mô-đun :mod:`!nntplib` đã được chỉnh sửa toàn diện, vì vậy các API của mô-đun này thường không tương thích với các API 3.1.

* Các đối tượng :class:`bytearray` không còn có thể được dùng làm tên tệp; thay vào đó, chúng nên được chuyển đổi thành :class:`bytes`.

* :meth:`!array.tostring` và :meth:`!array.fromstring` đã được đổi tên thành
  :meth:`array.tobytes() <array.array.tobytes>` và
  :meth:`array.frombytes() <array.array.frombytes>` để rõ ràng hơn. Các tên cũ đã bị phản đối. (Xem :issue:`8990`.)

* Các hàm ``PyArg_Parse*()``:

  * Định dạng "t#" đã bị loại bỏ: thay vào đó, hãy dùng "s#" hoặc "s*"
  * Các định dạng "w" và "w#" đã bị loại bỏ: hãy sử dụng "w*" thay thế

* Kiểu :c:type:`!PyCObject`, vốn không được khuyến nghị sử dụng từ phiên bản 3.1, đã bị loại bỏ. Để bọc các con trỏ C không trong suốt trong các đối tượng Python, thay vào đó nên sử dụng API :c:type:`PyCapsule`; kiểu mới có một giao diện được xác định rõ để truyền thông tin an toàn kiểu và một chữ ký đơn giản hơn khi gọi hàm hủy.

* Hàm :func:`!sys.setfilesystemencoding` đã bị loại bỏ vì có thiết kế thiếu sót.

* Hàm và phương thức :func:`random.seed` hiện thêm salt vào các seed chuỗi bằng hàm băm sha512. Để truy cập phiên bản trước của *seed* nhằm tái tạo các chuỗi của Python 3.1, hãy đặt đối số *version* thành *1*, ``random.seed(s, version=1)``.

* Hàm :func:`!string.maketrans` trước đây không được khuyến nghị sử dụng đã bị loại bỏ, thay vào đó là các phương thức tĩnh :meth:`bytes.maketrans` và
  :meth:`bytearray.maketrans`. Thay đổi này giải quyết sự nhầm lẫn về các kiểu được :mod:`string` hỗ trợ. Giờ đây, :class:`str`,
  :class:`bytes`, và :class:`bytearray` mỗi loại đều có các phương thức **maketrans** và **translate** riêng, cùng với các bảng dịch trung gian thuộc kiểu thích hợp.

  (Đóng góp bởi Georg Brandl; :issue:`5675`.)

* Hàm :func:`!contextlib.nested` trước đây đã bị phản đối nay đã bị loại bỏ để thay bằng một câu lệnh :keyword:`with` thuần túy có thể chấp nhận nhiều context manager. Kỹ thuật sau nhanh hơn (vì được tích hợp sẵn), đồng thời xử lý việc hoàn tất nhiều context manager tốt hơn khi một trong số chúng phát sinh ngoại lệ::

    with open('mylog.txt') as infile, open('a.out', 'w') as outfile:
        for line in infile:
            if '<critical>' in line:
                outfile.write(line)

  (Đóng góp bởi Georg Brandl và Mattias Brändström; `appspot issue 53094 <https://codereview.appspot.com/53094>`_.)

* :func:`struct.pack` giờ đây chỉ cho phép bytes đối với mã đóng gói chuỗi ``s``. Trước đây, nó chấp nhận các đối số dạng text và ngầm mã hóa chúng thành bytes bằng UTF-8. Điều này gây ra vấn đề vì nó đưa ra giả định về encoding chính xác, đồng thời encoding có độ dài biến đổi có thể không thành công khi ghi vào một phân đoạn có độ dài cố định của cấu trúc.

  Code như ``struct.pack('<6sHHBBB', 'GIF87a', x, y)`` nên được viết lại để sử dụng bytes thay vì text, ``struct.pack('<6sHHBBB', b'GIF87a', x, y)``.

  (Được David Beazley phát hiện và Victor Stinner sửa; :issue:`10783`.)

* Lớp :class:`xml.etree.ElementTree` giờ đây phát sinh một
  :exc:`xml.etree.ElementTree.ParseError` khi việc phân tích cú pháp thất bại. Trước đây, nó đã phát sinh một :exc:`xml.parsers.expat.ExpatError`.

* Giá trị :func:`str` mới, dài hơn trên các số thực có thể làm hỏng các doctest phụ thuộc vào định dạng đầu ra cũ.

* Trong :class:`subprocess.Popen`, giá trị mặc định của *close_fds* hiện là ``True`` trên Unix; trên Windows, giá trị này là ``True`` nếu ba stream tiêu chuẩn được đặt thành ``None``, và ``False`` trong các trường hợp khác. Trước đây, *close_fds* mặc định luôn là ``False``, điều này gây ra các lỗi hoặc điều kiện tranh đua khó giải quyết khi các file descriptor đang mở bị rò rỉ vào tiến trình con.

* Hỗ trợ HTTP 0.9 cũ đã bị loại bỏ khỏi :mod:`urllib.request` và :mod:`http.client`. Hỗ trợ này vẫn còn ở phía máy chủ (trong :mod:`http.server`).

  (Do Antoine Pitrou đóng góp, :issue:`10711`.)

* Các socket SSL ở chế độ timeout hiện phát sinh :exc:`socket.timeout` khi xảy ra timeout, thay vì một :exc:`~ssl.SSLError` chung chung.

  (Do Antoine Pitrou đóng góp, :issue:`10272`.)

* Các hàm gây hiểu lầm :c:func:`!PyEval_AcquireLock` và
  :c:func:`!PyEval_ReleaseLock` đã chính thức bị phản đối sử dụng. Thay vào đó, nên sử dụng các API nhận biết trạng thái luồng (chẳng hạn như :c:func:`PyEval_SaveThread` và :c:func:`PyEval_RestoreThread`).

* Do các rủi ro bảo mật, :func:`!asyncore.handle_accept` đã bị phản đối sử dụng và một hàm mới, :func:`!asyncore.handle_accepted`, đã được thêm vào để thay thế nó.

  (Do Giampaolo Rodola đóng góp trong :issue:`6706`.)

* Do cách triển khai mới của :term:`GIL`, không thể gọi :c:func:`!PyEval_InitThreads` trước :c:func:`Py_Initialize` nữa.
